💡 WHY HEAP?

Imagine an emergency room. Patients arrive constantly. You don't treat them in arrival order — you treat the most critical patient first.

A Heap lets you always find the "most important" in O(1) and insert/remove in O(log n).

💡 THE HEAP AHA
When you need the extreme element (min or max) repeatedly and efficiently — that's a Heap. Not sorting. Sorting gives you everything ordered. Heap gives you the one thing that matters right now.
1 WHAT IS A HEAP?
  • A Complete Binary Tree stored as an array
  • Satisfies the Heap Property (parent vs children order)
  • NOT sorted — only root is guaranteed extreme
  • Implements a Priority Queue ADT

📚 COMPLEXITY REASONING
OperationTimeWhy
offer(x) / insertO(log n)Bubble Up (height = log n)
poll() / remove rootO(log n)Sift Down (height = log n)
peek()O(1)Root is always index 0

⭐ Build Heap = O(n) — better than n × offer() = O(n log n)
⚡ CLUES THAT SCREAM HEAP

1. "Kth largest / smallest" → Min/Max Heap of size K

2. "Top K frequent" → Frequency map + Min Heap

3. "Merge K sorted lists" → Min Heap

4. "Running median" → Two Heaps (Max + Min)

📊 HEAP vs SORTING vs QUICKSELECT vs TREESET

💡 Use Heap for streaming Top-K. Use QuickSelect for single Kth query. Use Sorting for small N.
⚠️ IMPORTANT: No Decrease-Key in Java PriorityQueue
Java's PriorityQueue does NOT support decreaseKey() or arbitrary removal.

To update a value: remove the old object (O(n)) and add the new one, or reinsert with updated priority.

For Dijkstra's algorithm, use a boolean[] visited with stale entries, or consider TreeMap for true decrease-key.
🔧 HEAPIFY — BUILD HEAP O(n) VISUAL
Input: [1, 3, 2, 7, 5, 4, 6]
Index 2 (value 2)
2 → children: 4, 6 ✅
Index 1 (value 3)
3 → children: 7, 5 ✅
Index 0 (value 1)
1 → children: 3, 2 ✅
Why O(n)? Only internal nodes (n/2) need sift-down. Leaves do 0 work. Total work = Σ(nodes at height h) × h = O(n).
⚡ 5-STEP HEAP THINKING FRAMEWORK
  1. What element do I need repeatedly? Largest? Smallest? Most frequent?
  2. Is heap size bounded? Top K → size K. Merge K → size K.
  3. Min or Max Heap? For largest → Min Heap (evict smallest). For smallest → Max Heap (evict largest).
  4. What's the comparator? Natural order? Custom? Lambda?
  5. What's the answer? Root value? Size? Sum?

PATTERN 1 — TOP-K (MIN HEAP OF SIZE K) LC 703 · EASY
When to Use: Keep K largest elements from a stream.
Input: k=3, nums=[4,5,8,2], add(3), add(5), add(10)
Output: 4, 5, 5
💡 AHA
To keep K largest, use a Min Heap of size K. When size > K, evict the smallest (root). Root = Kth largest! 
class KthLargest {
    private PriorityQueue<Integer> pq;
    private int k;

    public KthLargest(int k, int[] nums) {
        this.k = k;
        pq = new PriorityQueue<>(); // Min Heap
        for (int n : nums) add(n);
    }

    public int add(int val) {
        pq.offer(val);
        if (pq.size() > k) pq.poll(); // Evict smallest
        return pq.peek();
    }
}
PATTERN 2 — REPEATED MAX RETRIEVAL LC 1046 · EASY
When to Use: Always pick the largest element(s), operate, put result back.
Input: [2,7,4,1,8,1]
Output: 1
💡 AHA
Max Heap keeps the "king" at the top automatically after every operation. 
public int lastStoneWeight(int[] stones) {
    PriorityQueue<Integer> pq =
        new PriorityQueue<>(Collections.reverseOrder()); // Max Heap

    for (int s : stones) pq.offer(s);

    while (pq.size() > 1) {
        int a = pq.poll(); // largest
        int b = pq.poll(); // 2nd largest
        if (a != b) pq.offer(a - b);
    }
    return pq.isEmpty() ? 0 : pq.peek();
}

PATTERN 4 — TOP-K SMALLEST (MAX HEAP) LC 973 · MEDIUM
When to Use: Keep K smallest elements from a stream.
Input: points=[[1,3],[-2,2]], k=1
Output: [[-2,2]]
💡 AHA
To keep K smallest, use a Max Heap of size K. When size > K, evict the largest (root). Root = Kth smallest! 
public int[][] kClosest(int[][] points, int k) {
    // Max Heap by distance (safe comparator ✅)
    PriorityQueue<int[]> pq = new PriorityQueue<>(
        (a, b) -> Integer.compare(
            b[0]*b[0]+b[1]*b[1],
            a[0]*a[0]+a[1]*a[1])
    );

    for (int[] p : points) {
        pq.offer(p);
        if (pq.size() > k) pq.poll();
    }

    return pq.toArray(new int[k][]);
}
PATTERN 5 — FREQUENCY + TOP-K LC 347 · MEDIUM
When to Use: Find K most frequent elements.
Input: [1,1,1,2,2,3], k=2
Output: [1,2]
💡 AHA
HashMap for frequency, Min Heap of size K by frequency. Root = Kth most frequent. 
public int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int n : nums) freq.put(n, freq.getOrDefault(n, 0) + 1);

    // Min Heap by frequency
    PriorityQueue<Map.Entry<Integer, Integer>> pq =
        new PriorityQueue<>(Comparator.comparingInt(Map.Entry::getValue));

    for (Map.Entry<Integer, Integer> e : freq.entrySet()) {
        pq.offer(e);
        if (pq.size() > k) pq.poll();
    }

    int[] res = new int[k];
    for (int i = 0; i < k; i++) res[i] = pq.poll().getKey();
    return res;
}
PATTERN 6 — MERGE K SORTED LC 23 · HARD
When to Use: Merge K sorted lists into one sorted list.
Input: [[1,4,5],[1,3,4],[2,6]]
Output: [1,1,2,3,4,4,5,6]
💡 AHA
Min Heap of K heads. Poll → add next. Only K items in heap at once. O(N log K) time. 
public ListNode mergeKLists(ListNode[] lists) {
    if (lists == null || lists.length == 0) return null;

    PriorityQueue<ListNode> pq = new PriorityQueue<>(
        (a, b) -> Integer.compare(a.val, b.val) // Safe comparator ✅
    );

    for (ListNode node : lists) {
        if (node != null) pq.offer(node);
    }

    ListNode dummy = new ListNode(0);
    ListNode curr = dummy;

    while (!pq.isEmpty()) {
        ListNode min = pq.poll();
        curr.next = min;
        curr = curr.next;

        if (min.next != null) pq.offer(min.next);
    }
    return dummy.next;
}

PATTERN 7 — TWO HEAPS (MEDIAN) LC 295 · HARD
When to Use: Running median of a data stream.
Input: addNum(1), addNum(2), findMedian(), addNum(3)
Output: 1.5, 2.0
💡 AHA
Max Heap (lower half) + Min Heap (upper half). Median = average of tops (or larger half's top). 
class MedianFinder {
    private PriorityQueue<Integer> maxH = new PriorityQueue<>(Collections.reverseOrder());
    private PriorityQueue<Integer> minH = new PriorityQueue<>();

    public void addNum(int num) {
        maxH.offer(num);
        minH.offer(maxH.poll()); // balance

        if (maxH.size() < minH.size()) {
            maxH.offer(minH.poll());
        }
    }

    public double findMedian() {
        if (maxH.size() == minH.size()) {
            return (maxH.peek() + minH.peek()) / 2.0;
        }
        return maxH.peek();
    }
}
PATTERN 8 — GREEDY SCHEDULING LC 621 · MEDIUM
When to Use: Schedule tasks with cooldown.
Input: tasks=["A","A","A","B","B","B"], n=2
Output: 8
💡 AHA
Max frequency formula: `(maxFreq - 1) * (n + 1) + countMaxFreq`. Or use Max Heap + Queue for simulation. 
public int leastInterval(char[] tasks, int n) {
    int[] freq = new int[26];
    for (char c : tasks) freq[c - 'A']++;

    int maxFreq = 0, countMax = 0;
    for (int f : freq) maxFreq = Math.max(maxFreq, f);
    for (int f : freq) if (f == maxFreq) countMax++;

    return Math.max(tasks.length, (maxFreq - 1) * (n + 1) + countMax);
}

LC 23 · Merge K Lists HARD
Input: [[1,4,5],[1,3,4],[2,6]]
Output: [1,1,2,3,4,4,5,6]
Pattern: Min Heap
public ListNode mergeKLists(ListNode[] lists) {
    if (lists==null || lists.length==0) return null;
    PriorityQueue<ListNode> pq=new PriorityQueue<>((a,b)->Integer.compare(a.val,b.val));
    for (ListNode n : lists) if (n!=null) pq.offer(n);
    ListNode d=new ListNode(0), c=d;
    while (!pq.isEmpty()) {
        ListNode m=pq.poll(); c.next=m; c=c.next;
        if (m.next!=null) pq.offer(m.next);
    }
    return d.next;
}

public int minMeetingRooms(int[][] intervals) {
    Arrays.sort(intervals, (a,b)->Integer.compare(a[0], b[0]));
    PriorityQueue<Integer> pq = new PriorityQueue<>();
    pq.offer(intervals[0][1]);
    for (int i=1; i= pq.peek()) pq.poll();
        pq.offer(intervals[i][1]);
    }
    return pq.size();
}
