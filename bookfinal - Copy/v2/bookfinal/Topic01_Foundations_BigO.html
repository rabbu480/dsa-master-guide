🎬 THE REAL-WORLD STORY

Imagine transferring a 100 GB file to your friend across town. Should you send it over internet Wi-Fi or carry it on a physical USB drive?

  • Wi-Fi Transfer: Time scales linearly with file size (1 GB = 2 min, 100 GB = 200 min) $\rightarrow$ O(N)
  • Car Drive: Time is constant regardless of USB size (1 GB = 30 min, 100 GB = 30 min) $\rightarrow$ O(1)
💡 THE BIG-O AHA MOMENT
Big-O notation measures how runtime or memory scales as input size N grows to infinity, ignoring hardware speed differences!
🤔 WHY NOT MEASURE SECONDS?

Measuring code execution in milliseconds is unreliable in FAANG interviews because:

  • A fast CPU runs bad code quickly on small inputs.
  • Network jitter and background OS processes alter timings.
  • Big-O provides a universal mathematical upper bound guaranteed on all machines!

📐 THE 3 BIG-O REDUCTION RULES

Rule 1 — Drop Constants: O(2N + 5) $\rightarrow$ O(N). We care about growth rate, not constant multipliers.

Rule 2 — Drop Non-Dominant Terms: O(N^2 + 100N + 500) $\rightarrow$ O(N^2). As N grows to infinity, N^2 completely dominates N.

Rule 3 — Multi-Variable Rules: Array A size N, Array B size M $\rightarrow$ O(N + M) for sequential loops, O(N · M) for nested loops!

⚡ FAANG INTERVIEW PROBLEM SOLVING FRAMEWORK
  1. Clarify Constraints: Ask N limits ($N \le 10^5 \implies O(N \log N)$ target).
  2. State Brute Force: Mention naive solution and its complexity first.
  3. Identify Bottleneck: Find repeated work (e.g. repeated linear search $\implies$ HashMap/Binary Search).
  4. Optimize & Code: Write clean, bug-free Java code using standard naming.
  5. Dry Run Test Cases: Trace step-by-step with small inputs and edge cases!

RECURSION · CALL STACK · AUXILIARY SPACE
💡 AUXILIARY SPACE VS TOTAL SPACE

Interviewer asks: "What is the space complexity of your algorithm?"

  • Input Space: Memory used to hold input data (e.g. input array of size N).
  • Auxiliary Space: Extra memory created by your algorithm (data structures + recursion call stack).
  • Golden Rule: Unless specified otherwise, space complexity refers to Auxiliary Space!
🔄 RECURSION CALL STACK VISUALIZATION
Call Stack for `factorial(3)`:
factorial(3) -> waits for factorial(2)
  factorial(2) -> waits for factorial(1)
    factorial(1) -> returns 1 (Base Case!)
  factorial(2) -> returns 2 * 1 = 2
factorial(3) -> returns 3 * 2 = 6
Max Stack Depth = 3 -> Auxiliary Space: O(N)!

💼 COMMON JAVA INTERVIEW PITFALLS & BUGS
1. Integer Overflow in Binary Search:
`int mid = (left + right) / 2;` $\rightarrow$ ❌ Causes integer overflow if `left + right > 2^31 - 1`!
`int mid = left + (right - left) / 2;` $\rightarrow$ ✅ Safe formula!
2. String Immutability Overhead:
`String s += "a";` inside loop $\rightarrow$ ❌ Recreates string in O(N^2) total time!
`StringBuilder sb = new StringBuilder(); sb.append('a');` $\rightarrow$ ✅ O(1) amortized!

🔍 THE 4-STEP FAANG DRY RUN METHOD

Never declare your code finished until you perform a structured dry run on whiteboards or interview code pads!

  1. Pick a Small Concrete Input: e.g. `nums = [2, 7, 11]`, `target = 9`.
  2. Create a Variable State Table: Track loop counters, pointers, and memory variables explicitly.
  3. Step Line-by-Line: Execute code manually without skipping steps or assuming output!
  4. Test Edge Cases: Test empty inputs, single element arrays, duplicate values, and negative numbers.
