## 18. TIME & SPACE COMPLEXITY SUMMARY

| Problem Type | Time Complexity | Space Complexity | Notes |
| :--- | :--- | :--- | :--- |
| Classic Binary Search | O(log n) | O(1) | Iterative |
| First / Last Occurrence | O(log n) | O(1) | Extra checks |
| Search on Answer | O(log N × log M) | O(1) | N = array size, M = answer range |
| Search in 2D Matrix | O(log (m × n)) | O(1) | Treat as 1D array |
| Peak Element | O(log n) | O(1) | Bitonic array |
| Rotated Sorted Array | O(log n) | O(1) | Unique elements |

## 19. PATTERN RECOGNITION GUIDE
Look at the problem and identify the pattern:

* **Exact value in sorted array** ➔ Classic Binary Search
* **First / Last position of a target** ➔ First / Last Occurrence Templates
* **Smallest / Largest value satisfying a condition** ➔ Binary Search on Answer (Optimization Problems)
* **Matrix is sorted (row-wise & col-wise)** ➔ Treat as 1D Binary Search
* **Array is rotated sorted** ➔ Find pivot, then Binary Search in correct half
* **Bitonic / Mountain Array** ➔ Find peak, then search in increasing / decreasing part

## 20. BINARY SEARCH FLOW SUMMARY

**Is the array sorted?**
* **YES**
  * What are we looking for?
    * Exact Element ➔ Classic Binary Search
    * First / Last Occurrence ➔ First / Last Templates
    * Min / Max Satisfying Condition ➔ Binary Search on Answer
* **NO**
  * Can we sort it?
    * YES ➔ Sort + Classic Binary Search
    * NO ➔ Binary Search Not Applicable

## 21. BINARY SEARCH SUMMARY (KEY POINTS)
* Always think: Can I eliminate half of the search space?
* Define search space correctly.
* Choose the right template (classic / first / last / answer).
* Handle boundaries and edge cases.
* Avoid infinite loops by correct pointer updates.
* Dry run with small examples before coding.
* Write clean, bug-free, and well-commented code.

## 22. COMMON EDGE CASES

* **Array with 1 element**
  `nums = [5], target = 5 ➔ return 0`
* **Target not present**
  `nums = [1,2,3,4], target = 10 ➔ return -1`
* **All elements same**
  `nums = [7,7,7,7], target = 7 ➔ return first / last as per need`
* **First element target**
  `nums = [1,2,3,4], target = 1 ➔ return 0`
* **Last element target**
  `nums = [1,2,3,4], target = 4 ➔ return n-1`
* **Check for overflow in mid calculation**
  `int mid = left + (right - left) / 2; // safe`

## 23. DRY RUN TIPS
* Always write left, right, mid.
* Highlight the mid element.
* Write the comparison result.
* Update the pointers.
* Repeat until condition breaks.
* Finally, write the answer.

**Pro Tip:**
Practice dry run without coding first! It improves your problem-solving speed.
