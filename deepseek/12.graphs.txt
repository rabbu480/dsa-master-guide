> **“When do we convert an edge list into an adjacency list, and why?”**

### 🧠 First: 3 ways the graph can be given

#### 1️⃣ Edge List

Problem gives:

```text
edges = [
  [0,1],
  [0,2],
  [1,3],
  [2,3]
]
```

Meaning:

```text
0 -- 1
|    |
2 -- 3
```

This is just **connections**. It doesn't directly tell us all neighbors of a node.

---

#### 2️⃣ Adjacency List

We convert it to:

```text
0 → [1,2]
1 → [0,3]
2 → [0,3]
3 → [1,2]
```

Now asking:

> "Who are the neighbors of node 0?"

is immediate:

```java
graph.get(0)   // [1, 2]
```

---

### 🔥 So WHEN do we convert?

**Whenever the input is given as edges and our algorithm needs to traverse neighbors.**

Most commonly:

```text
DFS
BFS
Connected Components
Cycle Detection
Topological Sort
Shortest Path
```

Basically, almost every graph traversal algorithm.

---

### Example

Input:

```java
int[][] edges = {
    {0, 1},
    {0, 2},
    {1, 3},
    {2, 3}
};
```

We build:

```java
List<List<Integer>> graph = new ArrayList<>();

for (int i = 0; i < n; i++) {
    graph.add(new ArrayList<>());
}

for (int[] edge : edges) {
    int u = edge[0];
    int v = edge[1];

    graph.get(u).add(v);
    graph.get(v).add(u); // because UNDIRECTED
}
```

Result:

```text
0 → 1, 2
1 → 0, 3
2 → 0, 3
3 → 1, 2
```

Then DFS becomes natural:

```java
void dfs(int node) {
    visited[node] = true;

    for (int nei : graph.get(node)) {
        if (!visited[nei]) {
            dfs(nei);
        }
    }
}
```

### 🧠 Remember this

```text
INPUT
  ↓
edges [[u,v], [u,v]...]
  ↓
CONVERT
  ↓
Adjacency List
  ↓
DFS / BFS / Graph Algorithm
```

**But don't blindly convert every time.**

If the problem **already gives you an adjacency list**, use it directly.

And if it's a **grid**, we usually don't build an adjacency list at all—we treat the 4/8 neighboring cells as implicit edges.

Your Graphs handbook specifically separates **graph representation** from the traversal algorithms, so this is the right foundation to nail before DFS/BFS. 

**Next key concept:** directed vs undirected — because that determines whether we add **one edge or two** when converting.

### First fix the mental model

For:

```text

```

Initially:

```text

```

After:


we want:

```text
  0
  |
  1
```

```text

rank   = [1, 0, 0]
```

Then:

```java
union(1, 2);
```

`find(1)` gives `0`, so we merge:

```text
    0
   / \
  1   2
```

```text
parent = [0, 0, 0]
rank   = [1, 0, 0]
```

## ❌ Your mistake

You wrote:

```java
if(ra < rb) return ra;
else if(ra > rb) return rb;
```

`ra < rb` tells you **nothing about which tree should become the parent**.

Rank decides that.

Also, `union()` should normally return a **boolean**:

```text
true  → successfully merged
false → already same group → cycle
```

# ✅ Correct DSU

```java
class DSU {

    int[] parent;
    int[] rank;

    public DSU(int n) {

        parent = new int[n];
        rank = new int[n];

        for (int i = 0; i < n; i++) {
            parent[i] = i;
        }
    }

    int find(int x) {

        if (parent[x] != x) {
            parent[x] = find(parent[x]);
        }

        return parent[x];
    }

    boolean union(int a, int b) {

        int ra = find(a);
        int rb = find(b);

        // Already in same group
        if (ra == rb) {
            return false;
        }

        // Smaller tree goes under bigger tree
        if (rank[ra] < rank[rb]) {

            parent[ra] = rb;

        } else if (rank[ra] > rank[rb]) {

            parent[rb] = ra;

        } else {

            // Same rank → choose ra as root
            parent[rb] = ra;
            rank[ra]++;
        }

        return true;
    }
}
```

### One important correction

This:

```java
if (rank[ra] < rank[rb])
```

means:

> **Tree `ra` is shorter → attach `ra` under `rb`.**

Not:

```java
if (ra < rb)
```

The **node numbers don't matter**. `rank` matters.
