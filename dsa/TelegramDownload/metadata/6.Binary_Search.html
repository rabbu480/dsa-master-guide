1. WHEN TO USE BINARY SEARCH?

  • [✅] Data is sorted or can be converted to sorted.
  • [✅] We can eliminate half of the search space.
  • [✅] Answer looks like → F F F T T T (False → True)
  • [✅] We can check a condition in O(1) time.
  • [✅] Used for exact match, first/last occurrence, or finding answer in search space.

💡 AHA MOMENT

Binary Search is not about searching an element, it's about finding the boundary where the answer changes

Example: | F | F | F | F | T | T | T | T | |---|---|---|---|---|---|---|---|                                 ↑                             Find the FIRST T (transition point)

2. CLASSIC BINARY SEARCH TEMPLATE (EXACT MATCH)

int left = 0, right = n - 1;
while (left <= right) {
    int mid = left + (right - left) / 2; // safe mid

    if (nums[mid] == target) {
        return mid; // found
    } else if (nums[mid] < target) {
        left = mid + 1;      // search right half
    } else {
        right = mid - 1;     // search left half
    }
}
return -1; // not found

Why mid = left + (right - left) / 2 ? To avoid integer overflow that can happen in (left + right) / 2

⭐ INTERVIEW TIP

  • [•] Always decide what the array is trying to tell you.
  • [•] Define the condition, not the element.
  • [•] Think: What am I searching for?
  • [•] Dry run on examples before coding.

❌ COMMON MISTAKES

  • [❌] Wrong boundaries update (leads to infinite loop)
  • [❌] Using mid = (left + right) / 2 (overflow risk)
  • [❌] Not handling edge cases (empty array, size 1)
  • [❌] Wrong condition ( < vs <= )
  • [❌] Returning wrong index (first/last occurrence problems)

7. FIRST & LAST OCCURRENCE TEMPLATES

First Occurrence (Lower Bound) Find the first index where nums[mid] == target

int firstOccurrence(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    int ans = -1;

    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] >= target) {
            if (nums[mid] == target) ans = mid;
            right = mid - 1;   // move left
        } else {
            left = mid + 1;  // move right
        }
    }
    return ans;
}

Last Occurrence (Upper Bound) Find the last index where nums[mid] == target

int lastOccurrence(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    int ans = -1;

    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] <= target) {
            if (nums[mid] == target) ans = mid;
            left = mid + 1;   // move right
        } else {
            right = mid - 1;  // move left
        }
    }
    return ans;
}

PRO TIP: - For First occurrence → shrink right when equal - For Last occurrence → shrink left when equal

8. SEARCH IN ROTATED SORTED ARRAY (UNIQUE ELEMENTS)

Example: nums = [4,5,6,7,0,1,2], target = 0

  • Is nums[mid] == target?
  • YES → Return mid
  • NO ↓
    • Is left half sorted? (nums[left] <= nums[mid])
    • Is target in left half? nums[left] <= target < nums[mid]
      • YES → right = mid - 1
      • NO → left = mid + 1
    • Right half is sorted
    • Is target in right half? nums[mid] < target <= nums[right]
      • YES → left = mid + 1
      • NO → right = mid - 1

★ Always eliminate the half that is sorted first!

9. BINARY SEARCH ON ANSWER

When to Use? - Answer is not an element from array. - We are asked to find minimum / maximum value that satisfies a condition. - The condition is monotonic (T...T...T or F...F...F).

General Template

int left = 0;              // minimum possible answer
int right = (int)1e9;      // maximum possible answer
int ans = -1;

while (left <= right) {
    int mid = left + (right - left) / 2;
    if (isValid(mid)) {        // condition check
        ans = mid;             // store answer
        right = mid - 1;       // try for better (smaller) answer
    } else {
        left = mid + 1;        // try for bigger answer
    }
}
return ans;

Examples - Minimum days to make M bouquets - Koko eating bananas - Allocate minimum pages - Split array largest sum

11. COMMON MISTAKES & HOW TO AVOID THEM

Mistake Why It's Wrong Fix
Using (left + right) / 2 Can overflow when left and right are large Use left + (right - left) / 2
Incorrect boundary update Can cause infinite loop or wrong result Be careful with left = mid + 1 or right = mid - 1
Not handling edge cases Empty array, size 1 array, target not found Always test edge cases
Confusing first & last occurrence Logic difference in shrinking Remember: first → shrink right, last → shrink left
Wrong condition in rotated array Leads to eliminating wrong half Check which half is sorted first

14. BINARY SEARCH ON 2D MATRIX (ROW-WISE SORTED)

Example Matrix: | 1 | 3 | 5 | 7 | |---|---|---|---| | 10 | 11 | 16 | 20 | | 23 | 30 | 34 | 50 | | 60 | 65 | 70 | 80 |

Search = 34

Approach: 1. Treat matrix as 1D array. 2. Index mapping:

row = mid / m;
col = mid % m;
  1. Apply normal Binary Search.

Code:

int row = matrix.length, col = matrix[0].length;
int left = 0, right = row * col - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    int r = mid / col, c = mid % col;
    if (matrix[r][c] == target) return true;
    else if (matrix[r][c] < target) left = mid + 1;
    else right = mid - 1;
}
return false;

★ Works because each row is sorted and first element of a row is greater than last of previous row.

15. SEARCH IN PEAK ELEMENT (BITONIC ARRAY)

Bitonic Array (First increasing then decreasing) Array: [1, 3, 8, 12, 4, 2]
Search = 4

Steps: 1. Find the peak element index. 2. If target == peak -> return true 3. If target < peak -> Binary Search in left (increasing part) 4. If target > peak -> Binary Search in right (decreasing part)

Find Peak Index

int l = 0, r = n - 1;
while (l < r) {
    int mid = l + (r - l) / 2;
    if (arr[mid] < arr[mid + 1])
        l = mid + 1;
    else
        r = mid;
}
return l;

Binary Search in Decreasing Order

while (l <= r) {
    int mid = l + (r - l) / 2;
    if (arr[mid] == target)
        return true;
    else if (arr[mid] > target)
        l = mid + 1;
    else
        r = mid - 1;
}

16. SEARCH IN INFINITE / VERY LARGE ARRAY

Problem: Array is sorted but size is unknown or very large. Target = 15

... 1 3 7 9 12 15 18 21 ...
0 1 2 3 4 5 6 7

(low = 4, high = 7. Expanding Range)

Solution: 1. Find the range (low, high) where target can exist. 2. Apply Binary Search in that range.

1. Expand range:

low = high + 1;
high = high * 2;

until arr[high] >= target or arr[high] is out of bounds

2. Apply normal Binary Search between low and high.

✔ Time Complexity: O(log index_of_target)

19. PATTERN RECOGNITION GUIDE

Look at the problem and identify the pattern:

  • Exact value in sorted array ➔ Classic Binary Search
  • First / Last position of a target ➔ First / Last Occurrence Templates
  • Smallest / Largest value satisfying a condition ➔ Binary Search on Answer (Optimization Problems)
  • Matrix is sorted (row-wise & col-wise) ➔ Treat as 1D Binary Search
  • Array is rotated sorted ➔ Find pivot, then Binary Search in correct half
  • Bitonic / Mountain Array ➔ Find peak, then search in increasing / decreasing part
