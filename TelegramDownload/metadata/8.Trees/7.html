1 BST RULE

For every node N in BST

All values in Left Subtree < N < All values in Right Subtree

Example

All < 8
graph TD 8((8)) --> 3((3)) 8 --> 10((10)) 3 --> 1((1)) 3 --> 6((6)) 10 --> 14((14))
All > 8
  • ✔ Left subtree → smaller values
  • ✔ Right subtree → larger values
  • ✔ Inorder traversal gives sorted order
2 SEARCH IN BST

Idea: Use BST property to decide the direction.

if key == root.val    → found
else if key < root.val → go left
else                  → go right

Example

graph TD 8((8)) --> 3((3)) 8 --> 10((10)) 3 --> 1((1)) 3 --> 6((6)):::highlight 10 --> 14((14)) classDef highlight stroke:#ef4444,stroke-width:2px,stroke-dasharray: 5 5
Search: 6

8 > 6 → go left

3 < 6 → go right

6 == 6 → found
Complexity
Time: O(h)     Space: O(1) iterative / O(h) recursive
(h = height of tree)
3 INSERT INTO BST

Idea: Find correct position and insert.

Steps:

  1. If tree is empty → new node becomes root
  2. Else compare and go left or right
  3. Insert when NULL is found

4 DELETE FROM BST

Cases to handle when deleting node X:

Case 1: X is a leaf node

→ Just delete it.

→
graph TD 6((6)) --> 5((5))

Case 2: X has one child

→ Replace X with its child.

Case 3: X has two children

→ Replace X with Inorder Successor (smallest in right subtree) or Inorder Predecessor (largest in left subtree).

5 Kth SMALLEST ELEMENT (LC 230)

Idea: Inorder traversal of BST gives sorted order.

Steps:

  1. Do Inorder (Left → Root → Right)
  2. Count nodes
  3. When count == k → return node

Example

graph TD 8((8)) --> 3((3)) 8 --> 10((10)) 3 --> 1((1)) 3 --> 6((6)):::highlight 10 --> 14((14)) classDef highlight stroke:#2563eb,stroke-width:2px
Inorder: 1, 3, 6, 8, 10, 14

k = 3  →  Answer = 6
Complexity
Time: O(h + k)     Space: O(h)
(h = height, k = position of answer)
6 VALIDATE BST (LC 98)

Idea: Each node must lie in a valid range.

For every node: min < node.val < max

Steps:

  1. Use two bounds: min and max
  2. Check: min < node.val < max
  3. Recur Left → (min, node.val)
  4. Recur Right → (node.val, max)

Example

graph TD 8((8)) --> 3((3)) 8 --> 10((10)) 3 --> 1((1)) 3 --> 6((6)) 10 --> 14((14))
For node 6:
Range (3, 8) ✔

For node 14:
Range (10, +∞) ✔

All nodes satisfy → Valid BST
Complexity
Time: O(n)     Space: O(h)
7 LCA IN BST (LC 235)

Idea: Use BST property to find LCA.

If both p and q < root → go left
If both p and q > root → go right
Else → root is LCA

Example: p = 1, q = 14

graph TD 8((8)):::lca --> 3((3)) 8 --> 10((10)) 3 --> 1((1)):::pq 3 --> 6((6)) 10 --> 14((14)):::pq classDef lca fill:#fca5a5,stroke:#b91c1c,stroke-width:2px classDef pq stroke:#000,stroke-width:2px,stroke-dasharray: 5 5
1 < 8 and 14 > 8

→ 8 is LCA
Complexity
Time: O(h)    Space: O(1) iterative / O(h) recursive

BST PROPERTIES
  • ✔ Left < Root < Right
  • ✔ Inorder = Sorted
  • ✔ No duplicates (by default)
  • ✔ Efficient operations: O(h)
  • ✔ Balanced BST → O(log n)
⭐ REMEMBER
  • Think in terms of range.
  • Inorder is your best friend.
  • BST gives you direction.
8 INORDER = SORTED ORDER

Proof by Example

graph TD 8((8)) --> 3((3)) 8 --> 10((10)) 3 --> 1((1)) 3 --> 6((6)) 10 --> 14((14))
Inorder Traversal
(Left → Root → Right)

= 1, 3, 6, 8, 10, 14
(sorted order)
💡 Why?

All left < root < all right
So visiting Left → Root → Right gives increasing order.
