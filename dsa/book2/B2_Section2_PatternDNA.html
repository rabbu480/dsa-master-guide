PATTERN DNA: DFS (Recursive & Iterative) DNA #1
Parent Pattern
Tree / Graph Traversal
Children Patterns
Tree DFS, Grid DFS, Graph DFS, Trie DFS, Backtracking, Memoized DFS
Reusable Ideas
"Explore as far as possible along each branch before backtracking", LIFO state stack processing
Input Shape
Tree, Graph (Adjacency List/Matrix), 2D Grid, Node
Recognition Signals
"all paths", "connected components", "explore deeply", "valid path exists"
Decision Tree
If finding all possibilities/paths or deep traversal → Use DFS
Else if finding shortest path in unweighted graph → Use BFS
Reusable State
visited[] boolean array or HashSet, stack[] (explicit Deque or implicit call stack)
Top 3 Failure Modes
  • Forgetting to mark visited[u] = true before recursive calls, causing infinite loops in cyclic graphs.
  • StackOverflowError due to deep recursion limits (failing to switch to iterative stack).
  • Incorrect base case placement (e.g. checking bounds after array index access).
Interview Follow-Up
"How do you convert this to an iterative version?" → Use an explicit ArrayDeque stack, push start node, and pop/process in loop.
PATTERN DNA: Tree DFS DNA #2
Parent Pattern
DFS (Recursive & Iterative)
Children Patterns
Tree DP, LCA, Pre/In/Post Order Traversals, Tree Construction
Reusable Ideas
Bottom-up subproblem aggregation (post-order), Top-down path state passing (pre-order)
Input Shape
Binary Tree, N-ary Tree (TreeNode)
Recognition Signals
"maximum depth", "diameter of tree", "path sum", "invert tree", "same tree"
Decision Tree
If child returns are needed to compute parent value → Use Post-Order DFS
Else if passing path context downwards → Use Pre-Order DFS
Reusable State
Implicit recursion stack, global maximum variable for cross-path max tracking
Top 3 Failure Modes
  • Null root base case missing: forgetting if (root == null) return 0;
  • Assuming path must pass through root (e.g. Diameter / Max Path Sum can be strictly in a sub-branch).
  • Not updating global max before returning single-path contribution up the call stack.
Interview Follow-Up
"What if the tree is skewed and stack overflows?" → Use Morris Traversal O(1) space or iterative stack.
PATTERN DNA: Grid DFS DNA #3
Parent Pattern
DFS (Recursive & Iterative)
Children Patterns
Island Counting, Flood Fill, Word Search (Trie + Grid DFS)
Reusable Ideas
In-place matrix mutation for visited tracking, 4-directional delta array navigation
Input Shape
2D Matrix / Grid (char[][] or int[][])
Recognition Signals
"number of islands", "max area of island", "flood fill", "surrounded regions"
Decision Tree
If counting/modifying connected component regions → Use Grid DFS
Else if shortest path step count on grid → Use Grid BFS
Reusable State
DIRS = {{0,1},{1,0},{0,-1},{-1,0}}, matrix in-place sink grid[r][c] = '0'
Top 3 Failure Modes
  • Checking bounds grid[r][c] before validating 0 <= r < R && 0 <= c < C causing ArrayIndexOutOfBoundsException.
  • Forgetting to sink/mark cell visited, leading to infinite 4-way recursion loop.
  • Modifying input matrix when problem requires pristine original matrix (use visited boolean grid instead).
Interview Follow-Up
"Can you do this without modifying the grid?" → Pass a boolean[][] visited grid or use Union-Find.
PATTERN DNA: Graph DFS DNA #4
Parent Pattern
DFS (Recursive & Iterative)
Children Patterns
Cycle Detection (3-Color DFS), Topological Sort (DFS), Tarjan Bridges
Reusable Ideas
Explicit Adjacency List construction, 3-state coloring (White/Gray/Black) for cycle detection
Input Shape
Adjacency List List<List<Integer>>, Edge Array int[][]
Recognition Signals
"detect cycle in graph", "connected components", "course schedule DFS", "reconstruct itinerary"
Decision Tree
If graph has potential cycles or requires path backtracking → Use Graph DFS
Else if unweighted shortest path → Use Graph BFS
Reusable State
state[] (0=Unvisited, 1=Visiting, 2=Visited), parent[] array for undirected cycle tracking
Top 3 Failure Modes
  • Using 2-state boolean visited for directed cycle detection instead of 3-state (Gray/Visiting state is required).

  • Confusing directed cycle detection (back-edge to Gray node) with undirected cycle detection (edge to non-parent visited node).
Interview Follow-Up
"How to find critical connections / bridges?" → Tarjan's low-link discovery time DFS.

PATTERN DNA: Backtracking DFS DNA #6
Parent Pattern
DFS Family
Children Patterns
Subsets, Permutations, Combination Sum, N-Queens, Sudoku
Reusable Ideas
Choose → Explore → Unchoose pattern, decision tree space exploration
Input Shape
Array, String, Set of Choices
Recognition Signals
"generate all combinations", "subsets", "permutations", "solve puzzle"
Decision Tree
If problem demands generating EVERY valid state configuration → Use Backtracking
Else if problem asks for min/max/count of states → Use Dynamic Programming
Reusable State
path / currentChoice list, start index, used[] boolean array for permutations
Top 3 Failure Modes
  • Forgetting to copy res.add(new ArrayList<>(path)), resulting in empty path lists in result.
  • Forgetting the "Unchoose" backtrack step (path.remove(path.size() - 1)).
  • Not sorting array prior to duplicate skipping (if (i > start && nums[i] == nums[i-1]) continue;).
Interview Follow-Up
"How do you optimize redundant state exploration?" → Prune branches early or use Memoization DP if state repeats.
PATTERN DNA: Memoized DFS (Top-Down DP) DNA #7
Parent Pattern
DFS Family + Dynamic Programming
Children Patterns
1D/2D Top-Down DP, Memoized Game Theory, Target Sum
Reusable Ideas
Caching DFS recursive evaluation state in memo[][] array or HashMap
Input Shape
Array, Target Value, Grid, Game State
Recognition Signals
"number of ways", "can achieve target", "max score with overlapping choices"
Decision Tree
If search tree has duplicate overlapping sub-problems → Use Memoized DFS
Else if state transitions are simple and sequential → Use Bottom-Up Tabulation
Reusable State
memo[index][state] table initialized to sentinel value (e.g. -1 or null)
Top 3 Failure Modes
  • Initializing memo cache with 0 when 0 is a valid return value (causes cache miss re-computations).
  • Incomplete state representation in memo key (omitting a variable that changes recursion outcome).
  • Stack overflow on deep recursion inputs (convert to bottom-up DP).
Interview Follow-Up
"Convert this to Bottom-Up DP" → Reverse recursion tree order into iterative nested loops.
PATTERN DNA: BFS (Standard & Level-Order) DNA #8
Parent Pattern
Graph Traversal
Children Patterns
Multi-Source BFS, Topological Sort (Kahn's), Level Order Tree
Reusable Ideas
Level-by-level queue expansion guarantees shortest path in unweighted graphs
Input Shape
Graph, Tree, Grid
Recognition Signals
"shortest path in unweighted graph", "minimum steps", "level order"
Decision Tree
If finding shortest path in unweighted graph or processing levels → Use BFS
Else if graph has edge weights → Use Dijkstra / Bellman-Ford
Reusable State
Queue<Integer> q = new ArrayDeque<>(), visited[] boolean array
Top 3 Failure Modes
  • Marking node visited when POLLING from queue instead of OFFERING (causes duplicate node queue pushes).
  • Forgetting int size = q.size() snapshot at start of level loop when tracking steps.
  • Memory limit exceeded from pushing unvisited duplicate nodes.
Interview Follow-Up
"What if edges have weight 0 or 1?" → Use 0-1 BFS with ArrayDeque (push front for 0, push back for 1).

Parent Pattern
BFS Family
Children Patterns
Rotting Oranges, 01 Matrix, Pacific Atlantic Flow, Fire Spreading
Reusable Ideas
Pre-filling queue with ALL initial starting sources at distance 0 for simultaneous expansion
Input Shape
2D Grid / Graph with multiple starting points
Recognition Signals
"distance to nearest X", "spreading fire/infection", "multiple start points"
Decision Tree
If finding distance from any of N targets simultaneously → Use Multi-Source BFS

Interview Follow-Up
"What if sources start at different initial timestamps?" → Use PriorityQueue Dijkstra ordered by start time.

PATTERN DNA: Binary Search (Exact / Lower / Upper Bound) DNA #11
Parent Pattern
Divide and Conquer
Children Patterns
Binary Search on Answer, Rotated Sorted Array Search, Matrix BS
Reusable Ideas
Halving search space O(log N) on sorted monotonic inputs using lo/hi pointers
Input Shape
Sorted Array, Monotonic Function
Recognition Signals
"sorted array", "find first/last position", "O(log n) time complexity required"
Decision Tree
If searching value in sorted array → Use Standard Binary Search
Else if searching answer space range → Use Binary Search on Answer
Reusable State
lo = 0, hi = n - 1 (or n for lower bound), mid = lo + (hi - lo) / 2
Top 3 Failure Modes
  • Integer overflow using (lo + hi) / 2 instead of lo + (hi - lo) / 2.
  • Infinite loops caused by incorrect pointer updating (e.g. lo = mid without upper bias mid).
  • Off-by-one errors on boundary index handling.
Interview Follow-Up
"What if elements are duplicated?" → Lower bound contract hi = mid on match; Upper bound lo = mid + 1.
PATTERN DNA: Binary Search on Answer DNA #12
Parent Pattern
Search Family
Children Patterns
Koko Bananas, Capacity To Ship, Split Array Largest Sum, Aggressive Cows
Reusable Ideas
Binary searching on monotonic answer range [minPossible, maxPossible] with isValid(mid) checker
Input Shape
Array of constraints, Range of integers
Recognition Signals
"minimum capacity to...", "maximum min distance", "smallest velocity to finish in H hours"
Decision Tree
If optimizing min/max answer and isValid(x) is monotonic → Use BS on Answer
Else if answer space non-monotonic → Use Greedy / DP
Reusable State
lo = minVal, hi = maxVal, ans variable, isValid(mid) helper function
Top 3 Failure Modes
  • Defining wrong initial search space [lo, hi] (e.g. lo = 0 when min speed must be 1).
  • Non-monotonic predicate function: isValid(x) does not produce continuous T...TFF...F pattern.
  • O(N) checker function optimization failure causing TLE.
Interview Follow-Up
"How to handle float/decimal answer ranges?" → Use fixed iteration loop (e.g. 100 steps) or hi - lo > 1e-6.
PATTERN DNA: Two Pointers DNA #13
Parent Pattern
Array / String Traversal
Children Patterns
3Sum, Container With Most Water, Trapping Rain Water, Dutch National Flag
Reusable Ideas
Shrinking search space from both ends O(N) by leveraging sorting or greedy invariants
Input Shape
Sorted Array, String, 1D Sequence
Recognition Signals
"pair in sorted array", "palindrome check", "container water", "triplets summing to zero"
Decision Tree
If array is sorted and searching for pairs/triplets → Use Two Pointers
Else if contiguous subarray window optimization → Use Sliding Window
Reusable State
left = 0, right = n - 1
Top 3 Failure Modes
  • Applying opposite-end two pointers on UN SORTED arrays expecting monotonic convergence.
  • Not skipping duplicate elements in 3Sum (causing duplicate triplet results).
  • Pointer collision bounds check missing (e.g. left < right inside inner loops).
Interview Follow-Up
"How to generalize 3Sum to K-Sum?" → Use recursion reducing K-Sum to (K-1)-Sum down to 2Sum base case.

Array, String

PATTERN DNA: Prefix Sum DNA #15
Parent Pattern
Array State Precomputation
Children Patterns
Prefix Sum + HashMap (Subarray Sum = K), 2D Prefix Sum, Product Except Self
Reusable Ideas
Range sum [L..R] = prefix[R+1] - prefix[L] computed in O(1) after O(N) precomputation
Input Shape
1D Array, 2D Grid
Recognition Signals
"range sum queries", "subarray sum equals K", "continuous subarray sum divisible by K"
Decision Tree
If querying multiple range sums or finding subarray sum = K with negatives → Use Prefix Sum
Else if non-negative array contiguous window → Use Sliding Window
Reusable State
prefix[] array of size N+1, or running sum + HashMap<Sum, Count>
Top 3 Failure Modes
  • Forgetting to seed HashMap with map.put(0, 1) for prefix sum = K starting at index 0.
  • Off-by-one error: using size N prefix array instead of N+1.
  • Using sliding window on arrays containing negative numbers (fails because window is non-monotonic).
Interview Follow-Up
"How to answer 2D subgrid sum queries in O(1)?" → Build 2D Prefix Sum matrix with inclusion-exclusion formula.

PATTERN DNA: Monotonic Queue DNA #18
Parent Pattern
Array-State Family + Deque
Children Patterns
Sliding Window Maximum, Shortest Subarray with Sum at Least K, Constrained Subset Sum
Reusable Ideas
Double-ended queue maintaining monotonic elements to give O(1) window max/min
Input Shape
1D Array + Window Size K or Constraint K
Recognition Signals
"maximum of each sliding window", "shortest subarray sum >= K with negative numbers"
Decision Tree
If tracking min/max element over dynamic sliding window → Use Monotonic Queue
Else if static window average/sum → Use Simple Sliding Window
Reusable State

Interview Follow-Up
"Can we use PriorityQueue instead?" → Yes, but time complexity increases from O(N) to O(N log K).

PATTERN DNA: Union-Find (Disjoint Set) DNA #21
Parent Pattern
Graph-Algorithm Family
Children Patterns
Kruskal MST, Redundant Connection, Accounts Merge, Dynamic Islands
Reusable Ideas
Partition elements into dynamic disjoint sets; path compression + rank union yields O(α(N)) ≈ O(1)
Input Shape
Graph Edges, Disjoint Groups, Matrix Grid
Recognition Signals
"dynamic connectivity", "redundant edge cycle detection", "merge groups"
Decision Tree
If dynamically merging connected components or detecting undirected cycles → Use Union-Find
Else if static graph reachability traversal → Use DFS / BFS
Reusable State
parent[], rank[] arrays, component count

Interview Follow-Up

PATTERN DNA: Dijkstra's Algorithm DNA #22
Parent Pattern
Graph-Algorithm Family + Greedy
Children Patterns
Network Delay Time, Path With Minimum Effort, Swim in Rising Water
Reusable Ideas
Greedily process lowest distance unvisited node using PriorityQueue O((V+E) log V)
Input Shape
Weighted Graph / Grid (Non-Negative Weights)
Recognition Signals
"shortest path weighted graph", "minimum time/cost to reach node", "min effort path"
Decision Tree
If finding shortest path in non-negative weighted graph → Use Dijkstra
Else if unweighted graph → Use BFS
Else if negative weights present → Use Bellman-Ford
Reusable State
dist[] array initialized to INF, PriorityQueue<int[]> pq storing (node, dist)
Top 3 Failure Modes
  • Applying Dijkstra to graphs containing negative edge weights (loops endlessly or returns wrong result).
  • Forgetting stale node check if (d > dist[u]) continue; causing TLE on dense graphs.
  • Not initializing dist[start] = 0.
Interview Follow-Up
"What if graph has negative edges but no negative cycles?" → Use Bellman-Ford (Card #23).
PATTERN DNA: Bellman-Ford Algorithm DNA #23
Parent Pattern
Graph-Algorithm Family + DP
Children Patterns
Cheapest Flights Within K Stops, Negative Cycle Detection
Reusable Ideas
Relax all E edges V-1 times; N-th relaxation step detects negative weight cycles
Input Shape
Weighted Graph (Can contain negative edges)
Recognition Signals
"negative edge weights", "detect negative cycle", "shortest path with at most K stops"
Decision Tree
If graph has negative edges or step-count constrained shortest path → Use Bellman-Ford
Else if non-negative weights → Use Dijkstra
Reusable State
dist[] array, copy array cloneDist[] for K-stop constrained variants
Top 3 Failure Modes
  • For K-stops constraint: not using previous iteration's distance array copy (causes multi-step relaxation in single iteration).
  • Relaxing edges from unreachable nodes (must check dist[u] != INF first).
  • Higher time complexity O(V × E) compared to Dijkstra.
Interview Follow-Up
"How to find all-pairs shortest paths?" → Use Floyd-Warshall O(V³) algorithm.

PATTERN DNA: Dynamic Programming (SC→RBR→MTS Umbrella) DNA #27

1D DP, 2D Grid DP, 0/1 Knapsack, LCS, LIS, Interval DP, Bitmask DP, State Machine DP
Reusable Ideas
Optimal Substructure + Overlapping Subproblems; SC→RBR→MTS (Subproblem Choice → Recurrence Relation → State Memoization/Tabulation/Space)

Array, String, Grid, Numerical Target
Recognition Signals
"maximum profit", "minimum cost", "number of ways to reach", "longest common subsequence"

PATTERN DNA: Greedy (Exchange Argument) DNA #28

Make immediate locally optimal choice without backtracking; proven via Exchange Argument
Input Shape
Array, Intervals, Resource Costs

Decision Tree
If sorting reveals a choice that never needs re-evaluation → Use Greedy
Else if choice depends on future subproblem outcomes → Use DP
Reusable State
Sorted array, running maxReach, currentEnd
Top 3 Failure Modes
  • Applying greedy assumption without proof on problems requiring DP (e.g. 0/1 Knapsack fails greedy).
  • Sorting intervals by start time instead of end time for Activity Selection / Max non-overlapping intervals.
  • Off-by-one boundary comparison on interval overlaps.
Interview Follow-Up
"How do you prove greedy choice is correct?" → Use Exchange Argument: show swapping greedy choice with any other choice yields equal or worse result.
PATTERN DNA: Bit Manipulation / Bitmask DNA #29
Parent Pattern
Bitwise Operations
Children Patterns
Single Number, Subsets Bitmask, Bitmask DP, Reverse Bits
Reusable Ideas
XOR properties (x ^ x = 0, x ^ 0 = x), Bitmask state representation for N <= 32
Input Shape
Integers, Set of Small Choices (N <= 20)
Recognition Signals
"single number without extra memory", "count set bits", "power of two", "subset representation"
Decision Tree
If finding odd occurrence or storing subset of size N <= 30 → Use Bit Manipulation
Else if N > 32 → Use HashSet / boolean[]
Reusable State
Bitmask integer, Bitwise operators: AND (&), OR (|), XOR (^), NOT (~), SHIFTS (<<, >>)
Top 3 Failure Modes
  • Operator precedence error: bitwise operators have LOWER precedence than comparison (always use parentheses: if ((val & (1 << i)) != 0)).
  • Using signed right shift >> instead of unsigned >>> when dealing with negative integers.
  • Bit overflow for N >= 32 (use 1L << i for 64-bit long masks).
Interview Follow-Up
"How to clear lowest set bit in O(1)?" → Expression n &= (n - 1) clears lowest 1 bit (Kernighan's Algorithm).
