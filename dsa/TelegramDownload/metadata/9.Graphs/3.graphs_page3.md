# GRAPH PATTERN GUIDE
## PAGE 2 - GRAPH INPUT TYPES & CONSTRUCTION GUIDE
"Every graph interview begins by converting the input into the right representation."

### 1 PLAIN ENGLISH
* Interviewers rarely give you a graph directly.
* Instead they give edges, grids, matrices or node objects.
* Your first job is to identify the input and convert it into the correct graph representation.

### 2 INPUT TYPES (What Interviewers Give You)

| Type | 1 EDGE LIST | 2 WEIGHTED EDGE LIST | 3 GRID | 4 ADJACENCY MATRIX | 5 NODE GRAPH (OBJECTS) |
|---|---|---|---|---|---|
| **Example Input** | `[[0,1],[1,2],[2,3]]` | `[[2,1,1],[2,3,1],[3,4,1]]` | `1 1 0 1 0`<br>`1 1 1 0 0` | `0 1 0`<br>`1 0 1`<br>`0 1 0` | Node<br>Neighbors[] |
| **Typical Problems** | - Valid Path<br>- Connected Components<br>- Graph Valid Tree | - Network Delay<br>- Cheapest Flights<br>- Minimum Effort Path | - Number of Islands<br>- Flood Fill<br>- Rotting Oranges<br>- Pacific Atlantic | - Number of Provinces<br>- Dense Graph Problems | - Clone Graph |
| **Interview Frequency** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐☆☆ | ⭐⭐☆☆☆ |

### 3 BRAIN SWITCH
**INTERVIEW INPUT ->**
* **Edge List** -> Build AdjList
* **Weighted Edge List** -> Build Weighted AdjList
* **Grid** -> Treat Cell as Node
* **Adjacency Matrix** -> Convert or Traverse Directly
* **Node Graph** -> Use Existing Neighbors

**REPRESENTATION FIRST. ALGORITHM SECOND.**

### 4 GRAPH CONSTRUCTION GUIDE

| Input (Interview Gives) | How to Build | Output (Your Representation) | Notes |
|---|---|---|---|
| **Edge List**<br>`[[u,v], ...]` | **Build Adjacency List**<br>(Undirected / Directed) | `List<List<Integer>>` | Most common representation.<br>Optimal for sparse graphs. |
| **Weighted Edge List**<br>`[[u,v,w], ...]` | **Build Weighted Adjacency List** | `List<List<int[]>>`<br>Each `int[] = {neighbor, weight}` | Use `int[]` or `Pair<node, weight>` |
| **Grid**<br>`matrix[m][n]` | **Use directions (`dirs[]`)**<br>Treat valid cell as node | **Implicit Graph**<br>(no explicit structure needed) | Neighbor checks on the fly using `dirs[]` |
| **Adjacency Matrix**<br>`matrix[n][n]` | **Use matrix directly**<br>or convert to AdjList | `int[][] matrix` (or convert to `List<List<Integer>>`) | Good for dense graphs.<br>O(1) edge check. |
| **Node Graph**<br>Node object with neighbors[] | **Use existing neighbors directly** | **Node (given)**<br>(no conversion needed) | Already a graph.<br>Just use it. |

★ Adjacency List is the preferred choice for 95% of interview problems.

### 5 VISUAL CONVERSION EXAMPLES
1. **Edge List -> Adjacency List**
   Edge List: `[[0,1],[0,2],[1,2],[2,3]]` -> Adjacency List: `0 -> [1,2]`, `1 -> [0,2]`, `2 -> [0,1,3]`, `3 -> [2]`
2. **Weighted Edge -> Weighted AdjList**
   Weighted Edges: `[[0,1,4],[0,2,5],[1,2,1]]` -> Weighted AdjList: `0 -> [(1,4),(2,5)]`, `1 -> [(0,4),(2,1)]`, `2 -> [(0,5),(1,1)]`
3. **Grid -> Implicit Graph**
   Grid (1s and 0s) -> Implicit Graph (4-Directions)
4. **Matrix -> Graph**
   Matrix (0s and 1s) -> Graph
5. **Node Objects -> Graph**
   Nodes (given) -> Neighbor Links (Already Built)

### 6 BUILD -> PRINT -> VALIDATE (Never Skip This!)
1. Understand Input -> 2. Build Graph -> 3. Print Graph -> 4. Validate Structure -> 5. Start Algorithm

| Graph Type | How to Validate |
|---|---|
| **Adjacency List** | Print each node and its neighbors |
| **Weighted Graph** | Print each node with (neighbor, weight) |
| **Grid** | Print grid dimensions and values |
| **Matrix** | Print the entire matrix |
| **Node Graph** | Print each node and neighbor count |

**⚠️ IMPORTANT**
Never start DFS/BFS (or any algorithm) until your graph structure is verified.

### 7 COMMON JAVA BUILD TEMPLATES (Construction Only)
**1. Build Adjacency List `List<List<Integer>>`**
```java
int n = V; // number of nodes
List<List<Integer>> graph = new ArrayList<>();
for (int i = 0; i < n; i++)
    graph.add(new ArrayList<>());

// For undirected edge (u, v)
graph.get(u).add(v);
graph.get(v).add(u);
```

**2. Build Weighted Adjacency List `List<List<int[]>>`**
```java
int n = V;
List<List<int[]>> graph = new ArrayList<>();
for (int i = 0; i < n; i++)
    graph.add(new ArrayList<>());

// Edge (u, v, w)
graph.get(u).add(new int[]{v, w});
graph.get(v).add(new int[]{u, w});
```

**3. Directions Array (For Grid) `int[][] dirs`**
```java
int[][] dirs = {
    {1, 0},  // down
    {-1, 0}, // up
    {0, 1},  // right
    {0, -1}  // left
};
```

### 8 AHA MOMENTS
* 💡 The algorithm usually doesn't change.
* 💡 Only the graph representation changes.
* 💡 A Grid is an implicit graph.
* 💡 Weighted graphs store (neighbor, weight).
* 💡 Node graphs are already built.
* 💡 Always build before solving.

### 9 COMMON INTERVIEW MISTAKES
* ❌ Started coding before building the graph.
* ❌ Forgot reverse edge in undirected graph.
* ❌ Used wrong representation.
* ❌ Stored weight incorrectly.
* ❌ Forgot 1-index vs 0-index.
* ❌ Didn't validate the graph.
* ❌ Mixed node and weight positions.

### 10 INTERVIEW THINKING FLOW
**Flow 1:** Problem -> What input did interviewer give? -> (Edge List / Weighted Edge / Grid / Matrix / Node Graph) -> Choose Representation -> Build Graph -> Print Graph -> Validate Structure -> Ready for Algorithm

**Flow 2:** Problem (Understand) -> Input (What given) -> Representation (How to model) -> Helper Structure (visited, parent, indegree, dist, etc.) -> Algorithm (DFS / BFS / Dijkstra / Topo etc.) -> Tiny Logic Change (Per Problem) -> Dry Run (Example) -> Optimize (Time/Space)

### 11 SUMMARY
**REMEMBER**
* ✅ Input determines Representation.
* ✅ Representation determines Data Structure.
* ✅ Data Structure enables Algorithm.
* ✅ Never skip graph construction.

* 🧠 Good construction saves time.
* 🐛 Clear structure avoids bugs.
* 🏃 Strong foundation leads to fast solutions.
