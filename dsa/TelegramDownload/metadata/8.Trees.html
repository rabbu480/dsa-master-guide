1. TREE FOUNDATIONS

Tree vs Binary Tree vs BST

Tree

A hierarchical data structure. Each node can have 0 or more children. No ordering between child nodes.

Binary Tree

Each node has at most 2 children: Left and Right. No ordering.

Binary Search Tree (BST)

Left < Root < Right. Inorder traversal gives sorted order.

Types of Binary Trees

  1. Full: Every node has 0 or 2 children.
  2. Complete: All levels filled except possibly the last level, nodes as far left as possible.
  3. Perfect: All internal nodes have 2 children, leaves at same level.
  4. Balanced: $|height(L) - height(R)| \le 1$ for every node.
  5. Skewed: Every node has only 1 child.

Key Terminology

  • Node · Root · Edge · Parent/Child · Leaf
  • Height = edges to deepest leaf
  • Depth = edges from root
  • Level = Depth + 1

2. TRAVERSALS

2.1 Depth First Search (DFS)

  • Preorder (Root → Left → Right) | Order: 1-2-4-5-3-6-7 | AHA: Need parent first.
  • Inorder (Left → Root → Right) | Order: 4-2-5-1-6-3-7 | AHA: Sorted order in BST.
  • Postorder (Left → Right → Root) | Order: 4-5-2-6-7-3-1 | AHA: Children answers first.

2.2 Breadth First Search (BFS)

  • Level Order | Uses Queue | Order: 1-2-3-4-5-6-7 | Queue size = current level size.

3. TREE RECURSION TEMPLATE

The Recursion Flow

  1. Base Case: check and handle if (node == null) return ...;
  2. Faith: assume left and right subtrees return correct answer.
  3. Recur Left: left = solve(node.left);
  4. Recur Right: right = solve(node.right);
  5. Combine: use left & right results to compute current.
  6. Return answer.
Type solve(TreeNode node) {
    if (node == null) return ...; // Base Case
    Type left = solve(node.left);
    Type right = solve(node.right);
    return combine(left, right);
}

4. DFS PATTERN PROBLEMS (POSTORDER FOCUSED)

  1. Max Depth: 1 + max(left, right)
  2. Same Tree: left && right
  3. Invert Tree: Swap left and right, then recurse
  4. Diameter: max(diameter, left + right) at each node
  5. Balanced Tree: abs(left - right) <= 1 for all nodes

5. BFS PATTERN PROBLEMS

  1. Level Order Traversal (LC 102): Store level lists using Queue size iteration.
  2. Right Side View (LC 199): Capture the last node of each level iteration.
  3. Zigzag Level Order (LC 103): Reverse list insertion direction on odd levels.

6. BST BIBLE

  • BST Rule: Left Subtree < Node < Right Subtree
  • Search: key < root → go left; key > root → go right; else found.
  • Insert: find NULL leaf position and insert.
  • Delete: Case 1: Leaf (delete) | Case 2: 1 Child (bypass) | Case 3: 2 Children (successor swap).
  • Kth Smallest: Inorder traversal count up to K.
  • Validate BST: Recurse down checking range [min, max].

7. ADVANCED TREE PROBLEMS

  1. LCA in Binary Tree (LC 236): If both subtrees return non-null, root is LCA.
  2. Build Tree (Pre + In) (LC 105): Use preorder element as root, partition inorder array.
  3. Path Sum (LC 112): Subtract node value down to leaf; return true if target == 0.
  4. Serialize / Deserialize (LC 297): Convert to level-order string using commas and null markers.

8. REVISION CHEAT SHEET

  • Height: O(n) Time, O(h) Space
  • Diameter: O(n) Time, O(h) Space
  • Validate BST: O(n) Time, O(h) Space
  • LCA: O(n) Time, O(h) Space

1.3 KEY TERMINOLOGY

  • Node : Basic unit of a tree.
  • Root : Topmost node of the tree.
  • Edge : Connection between parent and child nodes.
  • Parent : Immediate ancestor of a node.
  • Child : Immediate descendant of a node.
  • Leaf Node : Node with no children.
  • Internal Node : Node with at least one child.
  • Siblings : Children of the same parent.
  • Depth of Node : Number of edges from root to the node (Root depth = 0).
  • Level of Node : Depth + 1 (Root level = 1).
  • Height of Node : Number of edges on the longest path from the node to a leaf.
  • Height of Tree : Height of the root node (Longest path from root to a leaf).
  • Path : Sequence of nodes connected by edges.
  • Subtree : A tree formed by a node and its descendants.

2. TRAVERSALS

Ways to visit every node of a tree

2.1 DEPTH FIRST SEARCH (DFS) TRAVERSALS

1 PREORDER (Root → Left → Right)

  • ORDER OF VISIT: 1 - 2 - 4 - 5 - 3 - 6 - 7
  • AHA MOMENT: Need parent first. Visit root before its children.
  • WHEN TO USE?:
  • Create / Copy / Clone Tree
  • Serialize Tree
  • Prefix expressions
  • Build Tree (with Inorder)

2 INORDER (Left → Root → Right)

  • ORDER OF VISIT: 4 - 2 - 5 - 1 - 6 - 3 - 7
  • AHA MOMENT: In BST, Inorder gives sorted order.
  • WHEN TO USE?:
  • BST Problems
  • Sorted order
  • Kth Smallest / Largest in BST
  • Validate BST (Iterative)

3 POSTORDER (Left → Right → Root)

  • ORDER OF VISIT: 4 - 5 - 2 - 6 - 7 - 3 - 1
  • AHA MOMENT: Need children's answers first. Process children before parent.
  • WHEN TO USE?:
  • Delete / Free Tree
  • Postfix expressions
  • Evaluate expressions
  • Height, Diameter, Balanced, LCA, Path Sum (etc.)

2.2 BREADTH FIRST SEARCH (BFS) TRAVERSAL (LEVEL ORDER)

  • ORDER OF VISIT (LEVEL ORDER): 1 - 2 - 3 - 4 - 5 - 6 - 7
  • AHA MOMENT: Need level by level. Use Queue. Queue size tells current level.

TEMPLATE (BFS LEVEL ORDER)

Queue<Node> q = new LinkedList<>();
q.offer(root);

while (!q.isEmpty()) {
    int size = q.size(); // nodes in current level
    for (int i = 0; i < size; i++) {
        Node node = q.poll();
        // process node
        if (node.left != null) q.offer(node.left);
        if (node.right != null) q.offer(node.right);
    }
}

2.3 DFS vs BFS

Feature DFS (Depth First Search) BFS (Breadth First Search)
Strategy Go deep to a leaf, then backtrack Visit level by level from left to right
Data Structure Stack (or Recursion) Queue
Time Complexity O(n) O(n)
Space Complexity O(h) (h = height of tree) O(w) (w = max width of tree)
Best For Path, Height, DP on trees, Backtracking Shortest path in unweighted tree, Level wise problems

2.4 WHEN TO USE WHICH TRAVERSAL?

  • Need parent before children? → Use Preorder
  • Need sorted order (BST)? → Use Inorder
  • Need children's results first? → Use Postorder
  • Need level by level? → Use BFS
  • Modify / Build / Serialize Tree? → Mostly Preorder
  • Delete / Free / Evaluate? → Mostly Postorder

FINAL MANTRA

  • Tree problems → Think DFS first.
  • Level problems → Think BFS first.
  • Understand the need, then choose the traversal.

Note: * $n$ = number of nodes * $h$ = height of tree * $w$ = maximum width of tree

3. TREE RECURSION TEMPLATE

Master this template, solve any tree problem!

3.1 THE RECURSION FLOW (FAITH → RECUR → COMBINE → RETURN)

  1. BASE CASE: Check and handle the base condition. if (node == null) return ...;
  2. FAITH: Assume left and right subtrees will give correct answers.
  3. RECUR LEFT: Recur for the left subtree. left = solve(node.left);
  4. RECUR RIGHT: Recur for the right subtree. right = solve(node.right);
  5. COMBINE: Use left and right results. Do the required work. ans = ...;
  6. RETURN: Return the final answer. return ans;

UNIVERSAL TEMPLATE

Type solve(Node* node) {
    if (node == null) {
        return ...;          // Base Case
    }

    Type left = solve(node.left);   // Recur Left
    Type right = solve(node.right); // Recur Right

    Type ans = ...;          // Combine
    return ans;              // Return
}

KEY IDEA

  • Break the problem into left and right subproblems.
  • Solve both (faith).
  • Combine their results.
  • Return the final answer up the recursion stack.

FAITH → You assume your recursive calls (left & right) are correct and return the right answer.

3.2 RETURN TYPE DECIDES THE RECURSION

Return Type What it Means Examples
int Return some value (height, count, sum, etc.) Max Depth, Diameter, Sum of Nodes
boolean Return true / false info Same Tree, Balanced Tree, Valid BST
TreeNode* Return a node LCA, Invert Tree, Search in BST
List / Vector Return a list of values / nodes All Paths, Level Order, Right Side View
void Do something (print / modify) Print Traversals, Populate Result

3.3 WHICH TRAVERSAL TO USE?

Goal Need Traversal Why?
Need parent before children? Parent info first Preorder (Root → Left → Right) Visit root before going to children.
Need sorted order (in BST)? Left first, then root, then right Inorder (Left → Root → Right) In BST, Inorder gives sorted order.
Need children's answers first? Children results before parent Postorder (Left → Right → Root) Process children before the root.
Need level by level? Level wise processing BFS (Level Order) Visit nodes level by level using Queue.

3.4 PREORDER vs INORDER vs POSTORDER (DECISION GUIDE)

  • What do you need?
  • Need parent information first? → YES → Use PREORDER (Root → Left → Right)
    • Examples: Build Tree (Pre + In), Serialize / Copy / Clone, Prefix Expression.
  • Need sorted order (in BST)? → YES → Use INORDER (Left → Root → Right)
    • Examples: BST Problems, Kth Smallest / Largest, Validate BST (Iterative).
  • Need children's results first? → YES → Use POSTORDER (Left → Right → Root)
    • Examples: Height / Diameter, Balanced Tree, Delete / Free Tree, Postfix Expression.
  • Need level wise? → YES → Use BFS (Level Order)
    • Examples: Level Order Traversal, Right Side View, Zigzag Traversal.

3.5 COMMON BASE CASES

  • if (node == null) return ...;
  • Used in almost all problems. Empty subtree.
  • if (node.left == null && node.right == null) return ...;
  • Leaf node condition.
  • if (node == target) return ...;
  • Found the target node.
  • if (k == 0) return ...;
  • Base case for depth / distance based problems.
  • if (low > high) return ...;
  • Used in tree construction from array / traversal.

3.6 TIPS TO MASTER RECURSION

  1. Draw the tree and try dry run.
  2. Identify what you need at each node.
  3. Decide return type.
  4. Write the template first.
  5. Fill the combine logic.
  6. Dry run again and verify.

GOLDEN RULE

  • Think small, Recur small, Combine smartly, Return clearly.

4. DFS PATTERN PROBLEMS (POSTORDER FOCUSED)

Most important tree problems follow DFS (Postorder). Master these patterns!

1. MAX DEPTH OF BINARY TREE

Example

        1
       / \
      2   3
     /   / \
    4   5   6
  • Output: 3

Column Details

  • 💡 AHA: Need the height of left and right subtrees first, then take max. That's Postorder.
  • ⚙️ Pattern: Postorder (Left → Right → Root)
  • Σ Formula:
  • 1 + max(left, right)
  • Base Case: if (node == null) return 0;
  • Code (Java): java int maxDepth(TreeNode root) { if (root == null) return 0; // Base Case int left = maxDepth(root.left); // Left int right = maxDepth(root.right); // Right return 1 + Math.max(left, right); // Combine }
  • Complexity: Time: O(n), Space: O(h) (h = height of tree)

2. SAME TREE

Example

Tree p:        Tree q:
     1              1
    / \            / \
   2   3          2   3
  /   /          /   /
 4   4          4   4
  • Output: true

Column Details

  • 💡 AHA: Both trees must match at current node, left subtree and right subtree. Return boolean.
  • ⚙️ Pattern: Postorder (Left → Right → Root)
  • Σ Formula:
  • Left && Right
  • Base Case:
    • Both null → true
    • One null → false
    • Values not equal → false
  • Code (Java): java boolean isSameTree(TreeNode p, TreeNode q) { if (p == null && q == null) return true; if (p == null || q == null) return false; if (p.val != q.val) return false; boolean left = isSameTree(p.left, q.left); boolean right = isSameTree(p.right, q.right); return left && right; // Combine }
  • Complexity: Time: O(n), Space: O(h)

3. INVERT BINARY TREE

Example

Input:         Output:
     1              1
    / \            / \
   2   3          3   2
  / \              / \
 4   5            5   4

Column Details

  • 💡 AHA: Need to process parent first, then swap children and recurse. That's Preorder.
  • ⚙️ Pattern: Preorder (Root → Left → Right)
  • Σ Formula:
  • Swap Left and Right
  • Base Case: if (node == null) return null;
  • Code (Java): java TreeNode invertTree(TreeNode root) { if (root == null) return null; // Base Case TreeNode temp = root.left; // Swap root.left = root.right; root.right = temp; invertTree(root.left); // Left invertTree(root.right); // Right return root; }
  • Complexity: Time: O(n), Space: O(h)

4. DIAMETER OF BINARY TREE

Example

        1
       / \
      2   3
     / \
    4   5
  • Output: 3 (Path: 4 → 2 → 1 → 3)

Column Details

  • 💡 AHA: Diameter can pass through any node. Need left height and right height at every node. Update global answer.
  • ⚙️ Pattern: Postorder (Left → Right → Root)
  • Σ Formula:
  • diameter = max(diameter, left + right)
  • return height = 1 + max(left, right)
  • Code (Java): java int diameter = 0; // global int diameterOfBinaryTree(TreeNode root) { height(root); return diameter; } int height(TreeNode node) { if (node == null) return 0; int left = height(node.left); int right = height(node.right); diameter = Math.max(diameter, left + right); // update return 1 + Math.max(left, right); // height }
  • Complexity: Time: O(n), Space: O(h)

5. BALANCED BINARY TREE

Example

        1
       / \
      2   3
     / \
    4   5
  • Output: true

Column Details

  • 💡 AHA: Every node must have left and right subtree heights difference <= 1. Need height of subtrees.
  • ⚙️ Pattern: Postorder (Left → Right → Root)
  • Σ Formula:
  • if |left - right| > 1 return -1 (imbalance found)
  • Else return 1 + max(left, right)
  • Code (Java): java boolean isBalanced(TreeNode root) { return height(root) != -1; } int height(TreeNode node) { if (node == null) return 0; int left = height(node.left); if (left == -1) return -1; int right = height(node.right); if (right == -1) return -1; if (Math.abs(left - right) > 1) return -1; return 1 + Math.max(left, right); }
  • Complexity: Time: O(n), Space: O(h)

POSTORDER - WHEN TO USE?

  • Need children's answers first.
  • Need height / depth / size.
  • Need info from left & right to compute current node.
  • Delete / Free / Evaluate expressions.
  • Diameter, Balanced, Max Path Sum, LCA (Binary Tree) etc.

QUICK RECAP

  • Height / Depth: 1 + max(left, right)
  • Diameter: left + right (update ans)
  • Balanced: abs(left - right) <= 1
  • Same Tree: left && right
  • Invert Tree: Swap + Recur

COMPLEXITY LEGEND

  • $n$ = number of nodes, $h$ = height of tree
  • Best Case (Balanced): Time: O(n), Space: O(log n)
  • Worst Case (Skewed): Time: O(n), Space: O(n)

⭐ FINAL MANTRA

Identify pattern → Write template → Apply formula → Handle base cases → Return correct type

5. BFS PATTERN PROBLEMS (LEVEL ORDER FOCUSED)

BFS = Level by Level using Queue

BFS TEMPLATE (LEVEL ORDER TRAVERSAL)

Queue<TreeNode> q = new LinkedList<>();
q.offer(root);

while (!q.isEmpty()) {
    int size = q.size(); // nodes in current level
    List<Integer> level = new ArrayList<>();

    for (int i = 0; i < size; i++) {
        TreeNode node = q.poll();
        level.add(node.val);

        if (node.left != null) q.offer(node.left);
        if (node.right != null) q.offer(node.right);
    }
    result.add(level);
}
  • Queue View: Shows elements entering and exiting the queue level by level.

1. LEVEL ORDER TRAVERSAL (LC 102)

Example

        1
       / \
      2   3
     / \ / \
    4  5 6  7
  • Output: [[1], [2,3], [4,5,6,7]]

Column Details

  • 💡 AHA: Need nodes level by level. Use Queue. Queue size tells current level.
  • ⚙️ Pattern: BFS (Level Order) using Queue
  • Σ Idea / Formula: Process all nodes in queue (size = current level). Add children to queue.
  • Code (Java): java List<List<Integer>> levelOrder(TreeNode root) { List<List<Integer>> res = new ArrayList<>(); if (root == null) return res; Queue<TreeNode> q = new LinkedList<>(); q.offer(root); while (!q.isEmpty()) { int size = q.size(); List<Integer> level = new ArrayList<>(); for (int i = 0; i < size; i++) { TreeNode node = q.poll(); level.add(node.val); if (node.left != null) q.offer(node.left); if (node.right != null) q.offer(node.right); } res.add(level); } return res; }
  • Complexity:
  • Time: O(n) (Every node visited once)
  • Space: O(n) (Queue can hold max nodes of last level)

2. RIGHT SIDE VIEW (LC 199)

Example

        1
       / \
      2   3 (selected)
     / \ / \
    4  5 6  7 (selected)
  • Output: [1, 3, 7] (Rightmost of each level)

Column Details

  • 💡 AHA: We need the last node of each level. In each level, the last node we pop is the rightmost.
  • ⚙️ Pattern: BFS (Level Order)
  • Σ Idea: In each level, pick the last node's value.
  • Code (Java): java List<Integer> rightSideView(TreeNode root) { List<Integer> res = new ArrayList<>(); if (root == null) return res; Queue<TreeNode> q = new LinkedList<>(); q.offer(root); while (!q.isEmpty()) { int size = q.size(); for (int i = 0; i < size; i++) { TreeNode node = q.poll(); if (i == size - 1) res.add(node.val); if (node.left != null) q.offer(node.left); if (node.right != null) q.offer(node.right); } } return res; }
  • Complexity: Time: O(n), Space: O(w)

3. ZIGZAG LEVEL ORDER (LC 103)

Example

        1         --> (Left to Right: 1)
       / \
      2   3       <-- (Right to Left: 3, 2)
     / \ / \
    4  5 6  7     --> (Left to Right: 4, 5, 6, 7)
  • Output: [[1], [3,2], [4,5,6,7]]

Column Details

  • 💡 AHA: Direction changes at every level. Use a flag.
  • ⚙️ Pattern: BFS + Direction Toggle
  • Σ Idea: If leftToRight -> add left to right. Else -> right to left.
  • Code (Java): java List<List<Integer>> zigzagLevelOrder(TreeNode root) { List<List<Integer>> res = new ArrayList<>(); if (root == null) return res; Queue<TreeNode> q = new LinkedList<>(); q.offer(root); boolean leftToRight = true; while (!q.isEmpty()) { int size = q.size(); LinkedList<Integer> level = new LinkedList<>(); for (int i = 0; i < size; i++) { TreeNode node = q.poll(); if (leftToRight) level.addLast(node.val); else level.addFirst(node.val); if (node.left != null) q.offer(node.left); if (node.right != null) q.offer(node.right); } res.add(level); leftToRight = !leftToRight; // toggle } return res; }
  • Complexity: Time: O(n), Space: O(w)

4. BFS TEMPLATE (REMEMBER THIS!)

// BFS Template
if (root == null) return;
Queue<TreeNode> q = new LinkedList<>();
q.offer(root);
while (!q.isEmpty()) {
    int size = q.size(); // nodes in current level
    for (int i = 0; i < size; i++) {
        TreeNode node = q.poll();
        // ---- Do something with node here ----
        if (node.left != null) q.offer(node.left);
        if (node.right != null) q.offer(node.right);
    } // ---- Level completed ----
}

Key Points

  • Use Queue
  • queue.size() = current level size
  • Process level by level
  • Add children for next level

5. HOW QUEUE WORKS IN BFS

Step Queue (Front → Back) Level Action Visual Flow
1 [1] 0 Start: push root Node 1 (Level 0)
2 [] → [2, 3] 1 Pop 1, push 2, 3
3 [2, 3] 1 Process level 1 Nodes 2, 3 (Level 1)
4 [] → [4, 5, 6, 7] 2 Pop 2 → push 4,5. Pop 3 → push 6,7.
5 [4, 5, 6, 7] 2 Process level 2 Nodes 4, 5, 6, 7 (Level 2)
6 [] 3 All nodes processed
7 [] - Queue empty, done!

WHEN TO USE BFS?

  • Need level by level processing
  • Shortest path in unweighted graphs
  • Minimum steps / transformations
  • Problems involving distance / levels
  • Tree view from top / side / bottom

BFS vs DFS (QUICK COMPARISON)

Feature BFS DFS
Strategy Level by Level Go Deep, then Backtrack
Data Structure Queue Stack / Recursion
Best For Level problems Path / Depth problems
Space O(max width) O(max depth)

QUICK RECAP

  • Use Queue for BFS.
  • queue.size() gives current level.
  • Process all nodes of a level together.
  • Add children for next level.
  • BFS = Clean + Level Order + Optimal (for shortest path problems).

⭐ FINAL MANTRA

Think Level by Level → Use Queue → Process Level → Add Children → Repeat → Get Answer

6. BST BIBLE (BINARY SEARCH TREE)

The most Important BST rules, operations and patterns

1. BST RULE

For every node N in BST: All values in Left Subtree < N < All values in Right Subtree

Example

        8
       / \
      3   10
     / \    \
    1   6   14
  • All < 8 on left side: 1, 3, 6

  • All > 8 on right side: 10, 14

  • Left subtree → smaller values

  • Right subtree → larger values
  • Inorder traversal gives sorted order

2. SEARCH IN BST

Idea: Use BST property to decide the direction. * if key == root.val → found * else if key < root.val → go left * else → go right

Example (Search: 6)

        8   (8 > 6 → go left)
       / \
      3   10 (3 < 6 → go right)
     / \    \
    1   6   14 (6 == 6 → found!)

Complexity

  • Time: O(h)
  • Space: O(1) iterative / O(h) recursive ($h$ = height of tree)

3. INSERT INTO BST

Idea: Find correct position and insert. Steps: 1. If tree is empty → new node becomes root 2. Else compare and go left or right 3. Insert when NULL is found

Example (Insert 7)

        8                     8
       / \                   / \
      3   10       →        3   10
     / \    \              / \    \
    1   6   14            1   6   14
                               \
                                7

Complexity

  • Time: O(h)
  • Space: O(1) iterative / O(h) recursive

4. DELETE FROM BST

Cases to handle when deleting node X:

Case 1: X is a leaf node

→ Just delete it.

      6                  6
     / \     →          /
    5   8              5

Case 2: X has one child

→ Replace X with its child.

      6                  6
     / \     →          / \
    5   8              5   7
       /
      7

Case 3: X has two children

→ Replace X with Inorder Successor (smallest in right subtree) or Inorder Predecessor (largest in left subtree).

      6                  7
     / \     →          / \
    5   8              5   8
       / \                / \
      7   9              4   9

Complexity

  • Time: O(h)
  • Space: O(1) iterative / O(h) recursive

5. Kth SMALLEST ELEMENT (LC 230)

Idea: Inorder traversal of BST gives sorted order. Steps: 1. Do Inorder (Left → Root → Right) 2. Count nodes 3. When count == k → return node

Example

        8
       / \
      3   10       Inorder: 1, 3, 6, 8, 10, 14
     / \    \      k = 3 → Answer = 6
    1   6   14

Complexity

  • Time: O(h + k)
  • Space: O(h) ($h$ = height, $k$ = position of answer)

6. VALIDATE BST (LC 98)

Idea: Each node must lie in a valid range. For every node: min < node.val < max

Steps: 1. Use two bounds: min and max 2. Check: min < node.val < max 3. Recur Left → (min, node.val) 4. Recur Right → (node.val, max)

Example

        8
       / \
      3   10       For node 6: Range (3, 8) ✓
     / \    \      For node 14: Range (10, +∞) ✓
    1   6   14     All nodes satisfy → Valid BST

Complexity

  • Time: O(n)
  • Space: O(h)

7. LCA IN BST (LC 235)

Idea: Use BST property to find LCA. * If both p and q < root → go left * If both p and q > root → go right * Else → root is LCA

Example (p = 1, q = 14)

        8  (1 < 8 and 14 > 8 → 8 is LCA)
       / \
      3   10
     / \    \
    1   6   14

Complexity

  • Time: O(h)
  • Space: O(1) iterative / O(h) recursive

BST CHEAT SHEET

Operation Idea Time Space
Search Use BST property O(h) O(1) / O(h)
Insert Find position & insert O(h) O(1) / O(h)
Delete Handle 3 cases O(h) O(1) / O(h)
Kth Smallest Inorder + count O(h + k) O(h)
Validate BST Use range (min, max) O(n) O(h)
LCA (BST) Use BST property O(h) O(1) / O(h)

8. INORDER = SORTED ORDER

Proof by Example

        8
       / \
      3   10       Inorder Traversal (Left → Root → Right)
     / \    \      = 1, 3, 6, 8, 10, 14 (sorted order)
    1   6   14

Why?

All left < root < all right. So visiting Left → Root → Right gives increasing order.

BST PROPERTIES

  • Left < Root < Right
  • Inorder = Sorted
  • No duplicates (by default)
  • Efficient operations: O(h)
  • Balanced BST → O(log n)

REMEMBER

  • Think in terms of range.
  • Inorder is your best friend.
  • BST gives you direction.

7. ADVANCED TREE PROBLEMS

Important Problems beyond Basics

1. LOWEST COMMON ANCESTOR IN BINARY TREE (LC 236)

Example

         3 (LCA)
       /   \
      5     1
     / \   / \
    6   2  0  8
       / \
      7   4
  • p = 5, q = 1 → LCA = 3

Column Details

  • 💡 AHA: Children report back. If both left and right return non-null, current node is LCA.
  • ⚙️ Pattern: Postorder (Left → Right → Root)
  • Σ Idea / Formula:
  • If root == null or root == p or root == q → return root
  • left = recurse(left), right = recurse(right)
  • If left != null and right != null → return root
  • Else return left if not null else right
  • Complexity: Time: O(n), Space: O(h)

2. CONSTRUCT BINARY TREE FROM TRAVERSALS (LC 105)

Example

  • Inorder: [9, 3, 15, 20, 7]
  • Preorder: [3, 9, 20, 15, 7]
        3
       / \
      9  20
        /  \
       15   7

Column Details

  • 💡 AHA: Preorder → Root comes first. Inorder → Left and Right parts. Build tree using indices.
  • ⚙️ Pattern: Recursive (Divide & Conquer)
  • Σ Idea / Formula:
  • First element in preorder = Root
  • Find root in inorder → split left & right
  • Recur for left part and right part
  • Complexity: Time: O(n), Space: O(n)
  • Preorder / Inorder Alignment:
  • Preorder: 1 2 4 5 3 6 7
  • Inorder: 4 2 5 1 6 3 7

3. SERIALIZE AND DESERIALIZE BINARY TREE (LC 297)

Example (Serialize)

        1
       / \
      2   3
     / \   \
    4   5   6
  • Serialized: [1, 2, 4, null, null, 5, 3, null, 6] (Level Order with nulls)

Column Details

  • 💡 AHA: Store structure + values. Use null marker for missing nodes.
  • ⚙️ Pattern: BFS (Level Order) or Preorder
  • Σ Idea / Formula:
  • Serialize → Traverse and add values (add nulls)
  • Deserialize → Rebuild tree from values
  • Complexity: Time: O(n), Space: O(n)

4. PATH SUM (LC 112 / 113)

Example (Sum = 22)

            5
           / \
          4   8
         /   / \
        11  13  4
       /  \      \
      7    2      1
  • Path: 5 → 4 → 11 → 2 (Sum = 22)

Column Details

  • 💡 AHA: Need root to leaf path. Keep subtracting from target. If leaf and target == 0 → valid path.
  • ⚙️ Pattern: DFS (Preorder)
  • Σ Idea / Formula:
  • target -= node.val
  • If leaf and target == 0 → true
  • Else check left and right
  • Complexity: Time: O(n), Space: O(h)

5. BUILD TREE FROM INORDER AND POSTORDER (LC 106)

        /  \

  • ⚙️ Pattern: Recursive (Divide & Conquer)
  • Σ Idea / Formula:
  • Last element in postorder = Root
  • Find root in inorder → split left & right
  • Recur for left part and right part
  • Complexity: Time: O(n), Space: O(n)

6. BURNING BINARY TREE (LC 2385)

Example

        1
       / \
      2   3
     / \   \
    4   5   6
       /
      7
  • Start Node = 5 (colored/highlighted in red)
  • Time to burn all nodes = 4

Column Details

  • 💡 AHA: Fire spreads in all 4 directions. Convert tree to graph (undirected). Do BFS from start node.
  • ⚙️ Pattern: Graph + BFS
  • Σ Idea / Formula:
  • Convert tree to undirected graph
  • BFS from start node
  • Count levels (time)
  • Complexity: Time: O(n), Space: O(n)

COMMON MENTAL MODELS

  • Need parent first → Preorder
  • Need sorted order → Inorder
  • Need children first → Postorder
  • Need level by level → BFS
  • Path / Root to Leaf → DFS (Backtrack)

Inorder + Postorder

  • Inorder: Left | Root | Right
  • Postorder: Left | Right | Root
  • Action: Use root from postorder

2. RECURSION - GOLDEN TEMPLATE (DFS)

The Recursion Steps

  1. BASE CASE (blue): Handle null / edge case
  2. FAITH (green): Assume left & right give correct answer
  3. RECUR LEFT (orange): Recur for left subtree
  4. RECUR RIGHT (red): Recur for right subtree
  5. COMBINE (purple): Use left & right results, do required work
  6. RETURN (dark): Return the final answer

Code Block

Type solve(Node node) {
    if (node == null)
        return ...;       // 1. Base Case

    Type left = solve(node.left);  // 3. Recur Left
    Type right = solve(node.right); // 4. Recur Right

    // 5. Combine
    Type ans = ...;

    return ans;           // 6. Return
}

REMEMBER: Return type decides what you can compute. Break every problem into left & right subproblems.
