💡 WHY DOES HEAP EXIST?

Imagine you run an emergency room. Patients arrive constantly. You don't treat them in arrival order — you treat the most critical patient first.

A sorted array would be too slow to re-sort every time a new patient arrives. A Heap lets you always find the "most important" in O(1) and insert/remove in O(log n).

💡 AHA MOMENT
When you need the extreme element (min or max) repeatedly and efficiently — that's a Heap. Not sorting. Sorting gives you everything ordered. Heap gives you the one thing that matters right now.
1 WHAT IS A HEAP?
  • A Complete Binary Tree stored as an array
  • Satisfies the Heap Property (parent vs children order)
  • NOT sorted — only root is guaranteed extreme
  • Implements a Priority Queue ADT

⚡ HEAPIFY — HOW IT WORKS

Insert → Bubble Up (Heapify Up)

  1. Add element at last position
  2. Compare with parent
  3. If violates heap property → swap
  4. Repeat until root or satisfied

Delete Root → Sift Down (Heapify Down)

  1. Swap root with last element
  2. Remove last (was root)
  3. Compare root with children → swap with smaller (min) or larger (max)
  4. Repeat until leaf or satisfied

Heap Sort (ascending)
int[] heapSort(int[] arr) {
  PriorityQueue<Integer> pq = 
    new PriorityQueue<>();
  for (int x : arr) pq.offer(x);
  int[] res = new int[arr.length];
  for (int i = 0; !pq.isEmpty(); i++)
    res[i] = pq.poll();
  return res;
}
// Time: O(n log n)  Space: O(n)
Kth Largest Utility
int kthLargest(int[] nums, int k) {
  // Min Heap of size k
  PriorityQueue<Integer> pq = 
    new PriorityQueue<>();
  for (int x : nums) {
    pq.offer(x);
    if (pq.size() > k) pq.poll();
  }
  return pq.peek();
}
// Time: O(n log k)  Space: O(k)

PATTERN 1
REPEATED MAX / MIN RETRIEVAL
e.g. Last Stone Weight, Task Scheduler
When to Use
  • Always pick the largest (or smallest) element
  • Do an operation on it
  • Put the result back
  • Repeat until 1 or 0 left
💡 AHA
The heap keeps the "king" at the top automatically after every operation.
Heap to Use
Max Heap

Template (Java)
// Last Stone Weight pattern
PriorityQueue<Integer> pq = 
  new PriorityQueue<>(Collections.reverseOrder());
for (int s : stones) pq.offer(s);

while (pq.size() > 1) {
  int a = pq.poll();  // largest
  int b = pq.poll();  // 2nd largest
  if (a != b) pq.offer(a - b);
}
return pq.isEmpty() ? 0 : pq.peek();

• Space: O(n)

PATTERN 2
TOP-K ELEMENTS
e.g. Kth Largest, Top K Frequent, K Closest Points
When to Use
  • Need K largest elements → use Min Heap size K
  • Need K smallest elements → use Max Heap size K
  • Need K most frequent → freq as key
  • Key trick: discard the worst, keep the best K
💡 AHA
"Keep the K best" = use a heap of opposite type as a filter. Min Heap removes smallest → keeps K largest.
Counterintuitive Rule
Top K Largest
→ Min Heap (size K)
Top K Smallest
→ Max Heap (size K)
Root = the "weakest survivor"
that gets replaced if better comes
Template — Top K Largest & Smallest
// Top K LARGEST → Min Heap of size K
PriorityQueue<Integer> pq = new PriorityQueue<>();
for (int x : nums) {
  pq.offer(x);
  if (pq.size() > k) pq.poll(); // evict smallest
}
// pq now has the K largest

// Top K SMALLEST → Max Heap of size K
PriorityQueue<Integer> pq2 = 
  new PriorityQueue<>(Collections.reverseOrder());
for (int x : nums) {
  pq2.offer(x);
  if (pq2.size() > k) pq2.poll(); // evict largest
}
Complexity
• Time: O(n log k)
(heap size stays K)

• Space: O(k)

vs Sorting:
O(n log n) + O(n)

PATTERN 3
MERGE K SORTED LISTS / ARRAYS
e.g. Merge K Sorted Lists, Find K Pairs Smallest Sums
When to Use
  • Have K sorted sources (lists, arrays, rows)
  • Need to merge into one sorted stream
  • Always pick the globally smallest current candidate
  • Pattern: poll() one → push its next
💡 AHA
Heap acts as a "tournament bracket" — K competitors, always the current winner advances.
Visual

Template — Merge K Sorted Lists
// Store [value, listIndex, nodeIndex]
PriorityQueue<int[]> pq = 
  new PriorityQueue<>((a, b) -> a[0] - b[0]);

// Init: add head of each list
for (int i = 0; i < lists.length; i++)
  if (lists[i] != null) 
    pq.offer(new int[]{lists[i].val, i, 0});

ListNode dummy = new ListNode(0), tail = dummy;
while (!pq.isEmpty()) {
  int[] cur = pq.poll();
  tail.next = lists[cur[1]]; tail = tail.next;
  lists[cur[1]] = lists[cur[1]].next;
  if (lists[cur[1]] != null)
    pq.offer(new int[]{lists[cur[1]].val, cur[1], 0});
}
return dummy.next;

• Time: O(N log k)
N=total nodes, k=lists

• Space: O(k)
heap has at most k items

PATTERN 4
TWO HEAPS — RUNNING MEDIAN
e.g. Find Median from Data Stream, Sliding Window Median
When to Use
  • Stream of numbers arrives one by one
  • Need median at any point
  • O(log n) insert, O(1) median query
  • Split stream into two halves
💡 AHA
Max Heap (left half) top = lower bound.
Min Heap (right half) top = upper bound.
Median = average of both tops (or the larger half's top).

Template — addNum + findMedian
PriorityQueue<Integer> maxH = 
  new PriorityQueue<>(Collections.reverseOrder());
PriorityQueue<Integer> minH = 
  new PriorityQueue<>();

void addNum(int num) {
  maxH.offer(num);
  minH.offer(maxH.poll()); // balance
  if (maxH.size() < minH.size())
    maxH.offer(minH.poll());
}

double findMedian() {
  if (maxH.size() == minH.size())
    return (maxH.peek() + minH.peek()) / 2.0;
  return maxH.peek(); // larger half
}
Invariant: maxH.peek() ≤ minH.peek() AND |size diff| ≤ 1
Complexity
• addNum: O(log n)
• findMedian: O(1)
• Space: O(n)

PATTERN 5
GREEDY SCHEDULING / COOLDOWN
e.g. Task Scheduler, Reorganize String, Process Tasks Using Servers
When to Use
  • Tasks have cooldown before repeating
  • Always process most frequent first
  • Use Max Heap for frequency
  • Use Queue to hold "cooling down" items
💡 AHA
Greedy: always pick the busiest available worker. Use a queue as a "waiting room" during cooldown.
Template — Task Scheduler (LC 621)
Map<Character, Integer> freq = new HashMap<>();
for (char c : tasks) freq.merge(c, 1, Integer::sum);

PriorityQueue<Integer> maxH = 
  new PriorityQueue<>(Collections.reverseOrder());
maxH.addAll(freq.values());

Queue<int[]> q = new LinkedList<>(); // [count, readyTime]
int time = 0;

while (!maxH.isEmpty() || !q.isEmpty()) {
  time++;
  if (!maxH.isEmpty()) {
    int cnt = maxH.poll() - 1;
    if (cnt > 0) q.offer(new int[]{cnt, time + n});
  }
  if (!q.isEmpty() && q.peek()[1] == time)
    maxH.offer(q.poll()[0]);
}
return time;

PATTERN 6
INTERVAL TRACKING & RESOURCE ALLOCATION
e.g. Meeting Rooms II, Single-Threaded CPU, Seat Reservation
When to Use
  • Intervals/events processed chronologically
  • Track currently active resources (rooms, CPU)
  • Min Heap holds end times of active items
  • If smallest end time ≤ next start time → reuse resource
💡 AHA
Sort intervals by start time. Min Heap tracks end times. The root of the heap represents the earliest resource to become free.
Template — Meeting Rooms II (LC 253)
int minMeetingRooms(int[][] intervals) {
  Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
  // Min Heap stores end times of active meetings
  PriorityQueue<Integer> heap = new PriorityQueue<>();

  for (int[] interval : intervals) {
    // Free room if earliest ending meeting is done
    if (!heap.isEmpty() && heap.peek() <= interval[0]) {
      heap.poll();
    }
    heap.offer(interval[1]); // allocate room
  }
  return heap.size(); // min rooms needed
}
Complexity
• Time: O(n log n)
• Space: O(n)

int lastStoneWeight(int[] stones) {
  PriorityQueue<Integer> pq = new PriorityQueue<>(Collections.reverseOrder());
  for (int s : stones) pq.offer(s);

int leastInterval(char[] tasks, int n) {
  int[] freq = new int[26];
  for (char c : tasks) freq[c-'A']++;
  int maxF = 0, maxC = 0;
  for (int f : freq) maxF = Math.max(maxF, f);
  for (int f : freq) if (f == maxF) maxC++;
  return Math.max(tasks.length, (maxF-1)*(n+1)+maxC);
}

ListNode mergeKLists(ListNode[] lists) {
  PriorityQueue<ListNode> pq = new PriorityQueue<>((a,b) -> a.val - b.val);
  for (ListNode h : lists) if (h != null) pq.offer(h);
  ListNode d = new ListNode(0), t = d;
  while (!pq.isEmpty()) {
    t.next = pq.poll(); t = t.next;
    if (t.next != null) pq.offer(t.next);
  }
  return d.next;
}

class MedianFinder {
  PriorityQueue<Integer> lo = new PriorityQueue<>(Collections.reverseOrder());
  PriorityQueue<Integer> hi = new PriorityQueue<>();
  void addNum(int num) {
    lo.offer(num); hi.offer(lo.poll());
    if (lo.size() < hi.size()) lo.offer(hi.poll());

Each bubble up/sift down traverses at most log₂(n) levels = height of tree
📐 COMPLEXITY DERIVATION (Not Memorized — Derived!)
Why is poll/offer O(log n)?
Complete binary tree with n nodes has height = ⌊log₂n⌋
Bubble Up / Sift Down does at most 1 comparison per level.
Therefore: T = O(height) = O(log n)
Why is Build Heap O(n) not O(n log n)?
Only nodes at internal levels need sift-down. Leaves (n/2 nodes) do 0 work.
Total work = Σ (nodes at height h) × h
= n/4 × 1 + n/8 × 2 + n/16 × 3 + ...
= n × Σ(h/2ʰ) = n × 2 = O(n)

This geometric series converges to 2, proving O(n) build heap.
Why Top-K is O(n log k) not O(n log n)?
Heap stays at most size K throughout.
Each offer + possible poll = O(log K).
n elements processed = n × O(log k) = O(n log k)
When k = n, this = O(n log n). When k << n, huge speedup!
❌ COMMON MISTAKES
  • Using b-a comparator → integer overflow! Use Integer.compare(b,a)
  • Calling poll() on empty heap → returns null, causes NPE
  • Thinking default Java PQ is Max Heap → it's Min Heap
  • Assuming heap gives sorted order → it doesn't
  • Using contains() for existence check → O(n), not O(log n)
  • Forgetting to sort intervals by start time before using heap for end times
  • Top-K confusion: Top K Largest → Min Heap (counterintuitive!)
🎯 EDGE CASES — ALWAYS CHECK
  • Empty heap: peek() returns null, poll() returns null
  • K = n: Top-K returns entire array
  • K = 1: Min Heap of size 1 = running minimum
  • All same elements: Two heaps — equal split
  • Single element: Median = that element itself
  • Interval overlap edge case: Meeting ends at t=5 and next starts at t=5 (<= vs <)
  • Extreme values: Summing priorities causes 32-bit int overflow

💼 GOLDEN RULES — NEVER FORGET
Rule 1 — The Opposition Rule
To keep the K largest → use a Min Heap (evict the smallest intruder)
To keep the K smallest → use a Max Heap (evict the largest intruder)
Rule 2 — The Heap is NOT sorted
Heap only guarantees root is min/max. The rest is unordered. Never iterate a heap expecting order.
Rule 3 — The Overflow Trap
(a, b) -> b - a can overflow. ALWAYS use Integer.compare(b, a).
Rule 4 — Ask This First
"What element should come out next?" → That element goes on top of your heap.
