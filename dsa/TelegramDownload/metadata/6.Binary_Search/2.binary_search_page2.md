### 6. VARIANTS OF BINARY SEARCH

| Variant | When to Use |
| :--- | :--- |
| **Classic Binary Search** | Exact match in sorted array |
| **First Occurrence** | Find first index of target |
| **Last Occurrence** | Find last index of target |
| **Search in Rotated Sorted Array** | Array is sorted but rotated |
| **Search in Peak Element** | Find peak element in bitonic array |
| **Binary Search on Answer** | Answer lies in a range, not searching element |

### 7. FIRST & LAST OCCURRENCE TEMPLATES

**First Occurrence (Lower Bound)**
Find the first index where `nums[mid] == target`

```java
int firstOccurrence(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    int ans = -1;
    
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] >= target) {
            if (nums[mid] == target) ans = mid;
            right = mid - 1;   // move left
        } else {
            left = mid + 1;  // move right
        }
    }
    return ans;
}
```

**Last Occurrence (Upper Bound)**
Find the last index where `nums[mid] == target`

```java
int lastOccurrence(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    int ans = -1;
    
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] <= target) {
            if (nums[mid] == target) ans = mid;
            left = mid + 1;   // move right
        } else {
            right = mid - 1;  // move left
        }
    }
    return ans;
}
```

> **PRO TIP:** 
> - For First occurrence → shrink right when equal
> - For Last occurrence → shrink left when equal

### 8. SEARCH IN ROTATED SORTED ARRAY (UNIQUE ELEMENTS)

Example: `nums = [4,5,6,7,0,1,2]`, target = 0

- **Is `nums[mid] == target`?**
  - **YES** → Return mid
  - **NO** ↓
    - **Is left half sorted? (`nums[left] <= nums[mid]`)**
      - Is target in left half? `nums[left] <= target < nums[mid]`
        - YES → `right = mid - 1`
        - NO → `left = mid + 1`
    - **Right half is sorted**
      - Is target in right half? `nums[mid] < target <= nums[right]`
        - YES → `left = mid + 1`
        - NO → `right = mid - 1`

**★ Always eliminate the half that is sorted first!**

### 9. BINARY SEARCH ON ANSWER

**When to Use?**
- Answer is not an element from array.
- We are asked to find minimum / maximum value that satisfies a condition.
- The condition is monotonic (T...T...T or F...F...F).

**General Template**
```java
int left = 0;              // minimum possible answer
int right = (int)1e9;      // maximum possible answer
int ans = -1;

while (left <= right) {
    int mid = left + (right - left) / 2;
    if (isValid(mid)) {        // condition check
        ans = mid;             // store answer
        right = mid - 1;       // try for better (smaller) answer
    } else {
        left = mid + 1;        // try for bigger answer
    }
}
return ans;
```

**Examples**
- Minimum days to make M bouquets
- Koko eating bananas
- Allocate minimum pages
- Split array largest sum

### 10. VISUALIZING BINARY SEARCH (BOUNDARY SEARCH)

Find First Occurrence of target = 4 in `nums = [1, 2, 4, 4, 4, 5, 6]`

**Step 1:**
```
  0   1   2   3   5   6
| 1 | 2 | 4 | 4 | 5 | 6 |
  ↑           ↑       ↑
 l=0         m=3     r=6
```
`nums[m] == 4`
`ans = 3`
`r = m - 1 = 2`

**Step 2:**
```
  0   1   3   4   5   6
| 1 | 2 | 4 | 4 | 5 | 6 |
  ↑   ↑       ↑       
 l=0 m=1     r=2
```
`nums[m] < 4 ? no`
`nums[m] == 4`
`ans = 1`
`r = m - 1 = 0`

**Step 3:**
```
  0   1   2   4   5   6
| 1 | 2 | 4 | 4 | 5 | 6 |
  ↑   ↑       ↑
 l=0 m=0     r=0
```
`nums[m] < 4`
`l = m + 1 = 1`
Loop stops (`l > r`)

**Answer = 1 (first index of 4)**

### 11. COMMON MISTAKES & HOW TO AVOID THEM

| Mistake | Why It's Wrong | Fix |
| :--- | :--- | :--- |
| **Using (left + right) / 2** | Can overflow when left and right are large | Use `left + (right - left) / 2` |
| **Incorrect boundary update** | Can cause infinite loop or wrong result | Be careful with `left = mid + 1` or `right = mid - 1` |
| **Not handling edge cases** | Empty array, size 1 array, target not found | Always test edge cases |
| **Confusing first & last occurrence** | Logic difference in shrinking | Remember: first → shrink right, last → shrink left |
| **Wrong condition in rotated array** | Leads to eliminating wrong half | Check which half is sorted first |
